# GEOWorkFlow 后台功能与操作指南

> 本文档是 AI 工作台的官方系统知识基线。它面向 GEOWorkFlow 后台管理员，说明功能定位、页面入口、业务逻辑、标准流程、权限边界、检查方法和故障恢复。文中的站内入口由服务端根据命名路由、当前后台前缀和管理员权限生成。

## 一、系统总览与工作方法

### 1. GEOWorkFlow 的产品定位

GEOWorkFlow 是一套面向生成式引擎优化、内容生产、站点运营和多渠道分发的管理系统。系统把数据观察、选题素材、内容生成、质量检查、文章管理、渠道分发、网站呈现和效果回收放在同一条业务链路中。管理员可以先用数据中心判断问题，再用内容资产准备生产资料，通过任务编排批量生成内容，经过风险扫描和质量检查后发布到本站或外部渠道，最后回到数据中心查看访问、分发、线索和 AI 可见性变化。

系统的核心对象包括任务、文章、标题库、关键词库、知识库、图片库、作者、分类、AI 模型、提示词、分发渠道和托管站点。任务保存一组可重复执行的生产配置；文章保存每次生产的结果；内容资产为任务提供可复用输入；AI 配置决定模型调用方式；分发配置决定文章到达哪些目标站点；数据中心负责解释最终结果。理解这些对象之间的关系，可以减少重复配置和误操作。

### 2. 完整运行链路

一条标准内容生产链路通常包含以下阶段：

1. 在 AI 配置中准备可用的对话模型，执行连接检测并确认模型状态正常。
2. 在内容资产中准备关键词、标题、知识资料、图片、作者和分类。
3. 创建任务，选择模型、提示词、内容资产、生成数量、运行方式和分发范围。
4. 启动任务。调度器把任务转为运行记录，队列和 Worker 异步完成文章生成、图片选择、质量检查与分发。
5. 在文章管理中检查草稿、风险、AI 质检、发布状态和失败原因。
6. 在分发管理中检查渠道健康状态、远端结果、重试记录和站点同步情况。
7. 在数据中心查看内容、流量、线索、分发和 AI 可见性指标，形成下一轮优化判断。

任务启动是异步过程。页面提示“已提交”表示运行请求已经进入队列，文章数量、分发状态和质量检查结果会随着 Worker 处理逐步更新。判断任务是否完成时，应同时查看任务运行状态、文章结果和失败记录，避免只根据按钮反馈下结论。

### 3. 后台导航与权限

后台使用统一侧边栏组织数据中心、AI 工作台、任务、文章、人工发布、内容资产、分发、网站、AI 配置、用户权限和系统设置。最近访问会记录管理员近期打开的页面，方便回到高频工作区。后台前缀可以部署为 `/admin`、`/geo_admin` 或子目录，因此帮助回答中的入口统一使用命名路由生成，管理员无需记忆固定地址。

普通管理员可以使用日常内容与运营功能。超级管理员或具备受保护工作流权限的管理员可以管理用户、系统更新、高风险分发配置、AI 工作台系统知识和其他受保护操作。看不到某个入口时，应先确认账号角色、账号状态和当前功能是否启用。系统会在服务端再次校验权限，手工拼接地址不能绕过授权。

### 4. 三步快速开始

首次使用可以按照“模型、资产、任务”三步完成最小闭环。先进入 AI 模型配置，新增模型并执行连接检测；再创建一个小型标题库和知识库，准备少量安全测试素材；最后创建任务，生成一至两篇草稿并关闭自动分发。确认文章内容、状态变化和日志均符合预期后，再逐步增加生成数量、图片和分发渠道。这个顺序可以把模型、资产、生成和发布问题分开定位。

## 二、AI 工作台

### 1. 功能定位与适用场景

AI 工作台提供后台功能问答、操作指南和可信站内导航。它适合回答“某个功能在哪里”“怎样完成一条流程”“一个状态代表什么”“失败后应该检查哪些页面”“两个模块怎样配合”等问题。回答会结合本系统知识库的相关章节，按问题复杂度组织直接结论、前置条件、步骤、结果检查、常见问题和下一步入口。

AI 工作台保存管理员自己的会话。管理员可以创建会话、连续追问、修改会话名称、查看历史消息和归档旧会话。会话属于当前管理员，其他管理员不能读取。第一条问题会生成简短本地标题；管理员手工改名后，后续回答不会覆盖该名称。历史消息采用分页读取，长会话可以加载更早内容。

### 2. 回答逻辑

每轮问题先在 AI 工作台专用系统知识库中检索相关章节。检索优先匹配功能名称、页面别名、章节标题和关键词；本地结果置信度不足时，再使用知识切片和可选向量能力补充召回。服务端去除重复章节、控制证据预算并固定本轮知识版本，然后把证据交给对话模型组织语言。模型负责表达，不能自行创建可信入口、图片或系统操作结果。

站内入口由服务端功能注册表生成。注册表验证命名路由是否存在、页面是否为稳定读取入口、当前管理员是否有权限以及后台前缀是否正确。模型正文中的链接仍按普通文本处理。截图也由服务端根据命中章节选择，模型生成的 Markdown 图片不会直接显示。

连续追问会参考上一条用户问题和上一轮命中的章节。例如先问“如何创建任务”，再问“这个需要哪些模型”，系统会提高任务配置章节的权重。历史助手正文只用于保持语言连贯，不能替代当前知识证据。知识不足时，回答会说明缺少的事实并提出一个必要问题。

### 3. 输出边界与异常处理

AI 工作台帮助回答没有系统写入权限。它不会声称已经创建任务、修改文章、发布内容、删除资料或执行升级。涉及实时数量、运行结果或业务数据时，应进入对应页面核对。后续启用的只读能力或执行工作流仍由能力注册表、参数校验、审批、幂等和审计控制，系统知识只提供说明。

生成过程中会依次显示准备、连接模型和生成状态。网络中断、模型超时、额度不足或模型不可用时，页面会保留用户问题并返回明确错误，不保存不完整的助手回答。管理员可以检查 AI 模型状态后重试。停止生成会取消当前前端请求，不会把未完成正文和截图写入历史。

相关入口：[[route:admin.ai.configurator|检查 AI 配置]]

## 三、数据中心与效果分析

### 1. 数据中心总览

数据中心汇总内容、访问、分发、线索和 AI 可见性信息。总览适合快速判断系统是否持续产出、流量是否变化、渠道是否异常以及线索是否需要处理。管理员应先确认时间范围和筛选条件，再比较指标。时间范围不同、统计口径不同或数据尚未聚合，都可能造成数字差异。

总览指标用于发现方向，不直接代替明细。出现文章数量下降时，应进入内容分析和任务管理检查生成情况；访问变化较大时，应进入流量分析查看路径、来源和爬虫；分发失败增加时，应进入分发分析和渠道健康页面；线索增加时，应进入线索管理确认状态和内容。

### 2. 内容分析

内容分析关注文章数量、状态、发布时间、分类、作者和生产趋势。它可以回答某段时间生成了多少内容、哪些分类更新较快、文章处于草稿还是发布状态等问题。文章被软删除或进入回收站后，部分口径会与可见文章列表不同，分析时需要确认是否包含已删除数据。

内容分析异常时，按“任务运行、文章状态、质量门禁、发布时间”顺序排查。任务没有启动会导致没有新文章；文章生成失败会留下运行错误；风险扫描或 AI 质检阻断会让文章停留在待处理状态；计划发布时间尚未到达时，文章仍不会出现在前台。

### 3. 流量与访问日志

流量分析展示访问趋势、热门页面、来源和访问日志。访问日志可用于定位请求时间、路径、状态和来源。系统能够识别常见搜索蜘蛛和 AI 爬虫，帮助判断生成式引擎或搜索引擎是否抓取站点。爬虫访问量代表抓取活动，不等同于收录、引用或最终用户访问。

当流量为空时，先检查时间范围、站点配置、日志采集和页面是否有真实访问；再确认缓存、反向代理和统计任务是否正常。只有单个页面为空时，检查文章是否发布、前台路由是否可访问、站点地图是否包含该页面以及目标站点是否已刷新。

### 4. AI 可见性

AI 可见性用于观察品牌或主题在生成式引擎中的提及、引用来源和诊断结果。一次观测通常包含运行记录、来源数据和结构化结果。管理员应结合观测问题、模型来源、时间和引用证据解读，单次结果可能受到模型版本、联网能力和采样波动影响。

持续优化时，先建立稳定观测词，再检查品牌实体、核心页面、可信证据和结构化内容是否一致。内容生产负责补齐主题覆盖，分发负责扩大可访问页面，站点 SEO 与 Schema 帮助机器理解页面，AI 可见性负责回收结果。观测失败时，检查来源 Provider、模型接口、网络策略、结构化输出和额度。

### 5. 线索与分发分析

线索分析统计前台表单提交、处理状态和时间变化。数据包含个人信息，只有授权管理员可以查看和导出。分发分析关注渠道任务、成功率、失败类型和远端状态。分析页面用于发现趋势，具体失败仍需进入分发任务或渠道详情查看错误和重试记录。

功能入口：[[route:admin.analytics|进入数据中心]]
相关入口：[[route:admin.analytics.content|查看内容分析]]
相关入口：[[route:admin.analytics.ai-visibility|查看 AI 可见性]]

## 四、任务管理与内容生产

### 1. 任务的作用

任务是一组可重复执行的内容生产配置。它把模型、提示词、标题来源、关键词、知识资料、图片、作者、分类、生成数量、运行计划和分发范围组合起来。任务适合周期性或批量内容生产。临时修改单篇文章时，可以直接使用文章编辑器；需要重复生成时，应把稳定规则放入任务。

功能入口：[[route:admin.tasks.index|进入任务管理]]
相关入口：[[route:admin.tasks.create|新建任务]]

### 2. 创建任务前的准备

创建任务前应确认以下事项：对话模型处于启用和可用状态；标题库有足够的未使用标题或任务允许循环；知识库正文与切片已准备；作者和分类有效；需要图片时图片库包含可用图片；需要分发时渠道健康且权限正确；质量检查策略与业务风险相符。

标题容量是常见启动条件。任务计划生成的数量超过可用标题数量时，系统会根据循环策略决定阻止、复用或继续。标题指纹和去重规则可以减少重复内容。任务使用多个知识库时，关联顺序会影响上下文组合，应把最关键资料放在前面，并控制单次输入规模。

### 3. 创建与编辑流程

1. 打开任务管理，选择新建任务。
2. 填写任务名称、状态、生成数量和运行方式。
3. 选择对话模型、提示词、标题库、知识库、图片库、作者和分类。
4. 设置质量策略、发布方式和分发范围。
5. 保存后查看启动前检查，处理模型、标题容量、知识切片或渠道提示。
6. 先用小批量运行验证文章格式、风险和分发结果，再增加批量数量。

编辑运行中的任务时，应注意当前运行记录已经保存配置快照。新设置通常影响后续运行，不会自动改变已经进入队列的文章。需要停止生产时，先暂停或停用任务，再检查队列中是否仍有已领取工作。批量启动会分别创建运行记录，单个任务失败不会自动代表其他任务失败。

### 4. 调度器、队列和 Worker

调度器负责在计划时间发现可运行任务，队列保存待处理工作，Worker 执行文章生成、质量检查和分发。Horizon 提供 Redis 队列监控、进程状态、等待时间和失败任务信息。任务状态更新采用幂等和租约控制，避免同一运行被重复领取。

任务长时间没有进展时，按以下顺序检查：任务是否启用且到达计划时间；Scheduler 是否持续运行；队列连接是否可用；Worker 或 Horizon 是否在线；默认模型是否可用；失败任务中是否有明确异常；数据库和 Redis 是否正常。恢复 Worker 后，应优先使用系统提供的重试或恢复机制，避免直接修改运行状态。

### 5. 状态与结果检查

任务列表展示启用状态、运行状态、最近时间和健康提示。运行记录展示待处理、处理中、完成、失败或取消等阶段。文章列表是最终结果来源。一次运行显示完成时，仍需检查预期文章数量、质量门禁和分发结果；一次运行显示失败时，已经成功生成的文章通常会保留。

任务停止或取消用于阻止后续工作，已经向外部渠道提交的请求可能仍由远端完成。涉及外部写入时，应同时检查分发日志和目标站点。重复点击启动可能触发幂等保护或形成新的独立运行，应根据页面反馈确认。

### 6. 常见问题

任务无法启动通常与模型未就绪、标题不足、必需素材缺失、权限不足或任务冲突有关。生成数量不足时，检查标题去重、质量阻断、模型失败和并发限制。文章内容偏离主题时，检查标题、提示词、知识库顺序和模型配置。图片缺失时，检查图片库数量、文件安全状态和文章插图策略。分发没有执行时，检查任务分发范围、文章发布状态和渠道健康。

## 五、文章管理与质量控制

### 1. 文章生命周期

文章保存标题、正文、摘要、分类、作者、状态、发布时间、SEO 信息、图片、来源任务和质量结果。文章可以由任务生成，也可以由管理员手工创建。常见状态包括草稿、待审核、已发布和回收站。具体按钮由当前状态和权限决定。

功能入口：[[route:admin.articles.index|进入文章管理]]
相关入口：[[route:admin.articles.create|新建文章]]

### 2. 编辑与发布

文章编辑器用于维护标题、正文、摘要、作者、分类、图片和 SEO 字段。保存草稿后，应重新打开或查看列表确认数据已经写入。发布前检查正文结构、事实、链接、图片替代文本、风险提示、发布时间和前台预览。计划发布依赖 Scheduler，发布时间到达后还要确认状态转换和站点缓存。

批量操作适合统一修改状态、导出或处理多篇文章。执行前核对筛选范围和选中数量。删除通常先进入回收站，恢复后保留文章及其关联；彻底清理应遵循系统留存和引用检查。文章关联分发记录时，本站状态变化不会自动撤回全部远端内容。

### 3. 风险扫描

风险扫描根据敏感词、内容规则和安全策略识别高风险文本。扫描结果包含问题位置、风险级别和处理建议。管理员可以修改正文后重检；具备权限的管理员可以在有充分理由时人工放行。人工放行需要记录原因，后续正文发生变化时旧放行可能失效。

风险扫描负责明确规则和敏感内容，AI 质检负责结构、质量和证据一致性。两者可以同时存在。发布前应分别查看，不能用一个结果替代另一个结果。

### 4. 文章 AI 质检

AI 质检把文章分段，构造证据和审核提示，调用指定模型返回结构化结果，再由本地校验器计算分数和结论。检查记录保存文章、任务、模型、提示词、策略、指纹和分段结果。正文、关键配置或证据发生变化后，旧结果会标记过期，需要重新检查。

质量策略可以决定只提示、阻断发布或允许人工放行。检查失败时，先查看模型就绪、提示词配置、结构化输出和分段状态；再判断是否为文章本身问题。批量重检由队列执行，页面进度会逐步变化。人工放行属于受保护操作，应填写具体依据。

### 5. Markdown 批量导出

文章列表可以准备 Markdown 批量导出。服务端按授权范围生成导出文件和短期下载令牌，避免把任意文件路径暴露给浏览器。导出数量、请求大小和下载次数受到限制。令牌过期后需要重新准备。导出内容用于备份或外部编辑时，还应保护文章中的业务信息。

### 6. 常见恢复路径

保存后看不到修改时，检查验证错误、会话状态和浏览器网络响应。发布被阻断时，依次查看风险扫描、AI 质检、必填字段和发布时间。前台看不到文章时，确认文章已发布、当前站点范围正确、分类和路由有效、缓存已刷新。分发失败时转到分发任务查看远端错误，避免在文章页反复发布。

## 六、内容资产

### 1. 内容资产总览

内容资产集中管理分类、作者、关键词库、标题库、图片库和知识库。资产可以被多个任务复用，修改后会影响后续生产。删除资产前，系统会检查任务、文章或其他对象引用。被引用资产需要先解除关系或保留，系统知识库还具有专门删除保护。

功能入口：[[route:admin.materials.index|进入内容资产]]

### 2. 分类与作者

分类决定文章在后台和前台的组织方式，通常包含名称、slug、说明和排序。slug 参与前台地址，应保持稳定、可读和唯一。已有文章引用分类时，删除会受到限制。修改分类名称后，检查前台导航、列表和 SEO 信息。

作者保存展示名称、简介、头像、网站和社交信息。文章通过作者建立署名。头像使用受管路径或安全上传，外部地址应通过出站策略。删除作者前要处理已有文章引用。需要统一品牌口吻时，可以建立少量清晰作者档案并在任务中固定选择。

### 3. 关键词库

关键词库用于组织主题词和标题生成输入。管理员可以创建库、逐条添加、批量导入、删除条目和查看使用情况。导入会校验数量、字符长度、空值和重复项。关键词应表达明确主题，过短、歧义或大量重复会降低标题和内容质量。

任务读取关键词库时会保存必要快照，后续修改不一定改变正在运行的批次。删除关键词前确认它是否参与标题生成或任务。批量导入后应抽查字符编码、换行和去重结果。

### 4. 标题库与 AI 批量生成

标题库保存待生产标题、关键词、使用次数和 AI 生成标记。管理员可以手工添加、导入或调用 AI 批量生成。AI 生成运行记录保存模型、关键词库、轮次、数量、状态、重试和取消信息。标题指纹用于在并发写入时去重。

创建 AI 标题批次前，确认模型可用、关键词库有内容、目标数量和轮次合理。提交后由队列执行，页面显示运行进度。失败批次可以按安全规则重试，取消会阻止尚未处理的工作。生成完成后抽查重复度、主题相关性和字符长度，再把标题库用于正式任务。

相关入口：[[route:admin.title-libraries.index|进入标题库]]

### 5. 图片库

图片库保存文章配图。上传会校验真实 MIME、扩展名、文件大小和路径，受管图片服务负责安全文件名、存储和引用清理。图片记录保存尺寸、标签、使用次数和文件身份。直接提交服务器路径默认关闭，避免路径穿越和任意文件引用。

删除图片时，系统先检查文章引用并在事务后清理不再使用的受管文件。图片在多个位置使用时，物理文件会继续保留。文章配图应使用清晰、版权可控且与内容相关的素材，并填写必要替代文本。

### 6. 普通知识库

普通知识库保存用于内容生成和检索的 Markdown、文本或 Word 资料。管理员可以创建、上传、编辑、预览切片和重建检索索引。资料元数据包括来源、业务线、生效日期、风险级别和审核状态。正式生产优先使用来源清晰、已经审核且风险较低的资料。

知识同步先解析标题和章节，再生成结构化切片。切片保存内容哈希、章节路径、策略、来源哈希和向量信息。有可用 Embedding 模型时生成真实向量；服务不可用且当前操作允许回退时，系统使用本地向量或关键词能力保持可检索。新切片在暂存区完成后原子替换，失败时旧 ready 切片继续服务。

知识内容变更会让依赖它的文章质量结果失效。任务正在运行时修改知识库，已开始的生成可能继续使用旧快照，后续生成使用新内容。重建索引前先确认正文完整；强制真实向量刷新需要可用的 Embedding 模型。

功能入口：[[route:admin.knowledge-bases.index|进入知识库]]

### 7. AI 工作台系统知识库

「GEOWorkFlow 后台功能与操作指南（AI 工作台专用）」是受保护系统知识库。它由官方 Markdown 基线创建，保存稳定系统键、官方版本、内容哈希、同步时间和自定义状态。所有管理员可以查看，具备受保护工作流权限的管理员可以编辑正文、查看差异和恢复修订。

系统知识库在后台、API、CLI 和数据库外键层均有删除保护。编辑页会提示修改影响全部管理员的 AI 工作台回答。保存前系统检查必需章节、字符规模和 route 指令；保存成功后记录修订并提交索引。索引失败时继续使用旧 ready 切片或随代码基线。官方升级发现本地已自定义时会保留本地正文，并提示新的官方版本可用。

## 七、企业知识库与 URL 导入

### 1. 企业知识库

企业知识库适合把多个来源整理成可审查、可修订和可发布的知识项目。项目包含来源、解析结果、草稿、修订、校验和发布目标。管理员先创建项目和来源，再触发解析与草稿生成，检查结构和证据后发布到普通知识库供任务使用。

功能入口：[[route:admin.enterprise-knowledge.index|进入企业知识库]]

来源可能来自文件、网页或业务资料。抓取和解析经过出站安全、大小、类型和权限检查。草稿保存来源关联，校验会检查缺失章节、冲突和风险。发布会形成新的知识修订或目标知识库内容，不应跳过人工审查。恢复历史修订时，系统保留后续审计链。

企业知识更新失败时，检查来源可访问性、文件格式、网络策略、模型状态和校验信息。已经发布的知识库通常继续可用，失败草稿可以修复后重新生成。

### 2. URL 导入

URL 导入把外部网页经过抓取、解析、预览和确认后写入系统。创建导入任务时提交目标 URL 和必要选项；安全客户端校验协议、主机、重定向、响应大小和内容类型，阻止本地地址、私有网络和危险重定向。解析结果先进入预览，管理员确认后再提交到目标资产。

预览阶段应检查标题、正文完整性、编码、重复内容和来源。提交阶段具有幂等保护，重复请求不会无条件创建多份相同内容。失败时查看任务状态和日志，区分 DNS、连接、响应状态、大小限制、解析规则和目标写入问题。

功能入口：[[route:admin.url-import|进入 URL 导入]]

## 八、内容分发与托管站点

### 1. 分发总览

分发模块负责把文章和站点设置同步到外部渠道。渠道类型包括 GEOWorkFlow Agent、WordPress REST 和通用 HTTP API。每种渠道保存目标地址、认证信息、能力、状态和安全配置。渠道密钥使用加密存储，页面和日志只显示必要摘要。

功能入口：[[route:admin.distribution.index|进入内容分发]]

### 2. 渠道配置与健康检查

创建渠道时选择类型，填写名称、目标地址、认证方式和必要参数。保存前检查 URL、HTTPS、权限和目标接口版本。系统出站安全层会解析主机并阻止私有网络、回环地址、危险端口和不安全重定向。WordPress 需要 REST 权限和媒体能力；通用 HTTP API 需要与目标契约一致；GEOWorkFlow Agent 会协商版本和前端能力。

健康检查验证连接、认证和基本能力。检查成功只说明当前探测可用，正式发布仍可能受到内容、媒体、额度或远端业务规则影响。渠道暂停后不再接收新分发，已经提交的外部请求需要到任务记录确认。

### 3. 分发任务与重试

文章进入分发后会创建任务和日志，记录目标渠道、操作类型、请求摘要、远端标识、状态和错误。发布、更新、删除和设置同步具有独立幂等键。外部请求超时后，系统会先判断是否可能已经成功，再决定重试或对账，降低重复发布风险。

失败排查顺序为：渠道状态和认证、目标 URL 与网络、远端响应状态、请求大小和媒体、契约版本、幂等记录。修复配置后使用页面提供的重试。远端已经产生内容时，先读取远端标识或执行对账，避免重复创建。

### 4. 设置同步与预览

站点设置同步把品牌、导航、首页模块或其他受支持配置发送到目标站点。执行前可以查看单站或批量预览，确认差异、目标和风险。批量执行会为每个站点保存独立结果，部分失败可以单独恢复。目标站点不支持某项能力时，能力协商会阻止或跳过该项。

### 5. 托管站点

托管站点由 GEOWorkFlow 管理子域、文章分配、发布、配额、缓存、索引和生命周期。分配请求先检查根域、主机冲突、站点容量和任务关系，再创建站点档案。站点发布会构建页面、站点地图、结构化数据和发现文件，并记录内容指纹。

托管站点状态可能处于申请、准备、可用、维护或失败。站点无法访问时，检查域名解析、Nginx 配置、证书、站点档案、文章分配、缓存和健康探测。删除或释放站点前必须完成影响预检，确认文章、域名和远端资源范围。

功能入口：[[route:admin.distribution.hosted-sites.index|进入托管站点]]

## 九、人工发布与浏览器运营助手

### 1. 人工发布工单

人工发布用于需要管理员在第三方平台完成最终操作的场景。工单关联文章、平台身份、账号、执行人、计划时间和状态。常见流程为创建、分配、领取、执行、回填结果和完成。系统可以提示重复发布和风险，但最终平台操作由授权人员确认。

功能入口：[[route:admin.manual-publications.index|进入人工发布]]

工单创建前确认文章已经审核、目标账号正确、平台规则允许发布。执行人完成发布后回填远端地址、状态和说明。失败或取消应记录原因，方便后续排查。CSV 导出包含业务记录，应按权限保存和传递。

### 2. Chrome 运营助手

Chrome 运营助手通过设备授权协议连接浏览器扩展。扩展生成设备码，管理员在后台审核并批准，客户端换取受限令牌后领取允许的人工发布任务。会话包含心跳、领取、回执和撤销，权限变化或令牌撤销会终止后续访问。

功能入口：[[route:admin.account.browser-clients.index|管理浏览器运营助手]]

浏览器助手可以把经过确认的内容填入支持的平台草稿界面。知乎等平台的最终提交仍由人员检查并点击，系统不绕过平台验证。扩展只访问清单声明的页面和 GEOWorkFlow 接口，密钥保存在受限存储中。设备丢失或人员离开时，应立即撤销客户端。

### 3. PWA 与扩展的区别

PWA 把 GEOWorkFlow 后台安装为独立窗口，适合日常管理和会话；浏览器扩展负责在外部平台页面执行受控填充。PWA 不获得第三方页面权限，扩展也不替代后台的权限、审批和审计。出现连接问题时，分别检查后台登录、PWA 缓存、扩展版本、设备授权和目标平台页面。

## 十、网站、主题与线索

### 1. 网站基础设置

网站设置维护站点名称、品牌、Logo、基础展示和文章详情广告。保存后应在前台首页、文章页、浏览器标题、Open Graph 和结构化数据中核对。Logo 和图片使用安全文件路径；外部资源要符合出站策略。品牌字段为空时，主题可能使用默认值。

功能入口：[[route:admin.site-settings.index|进入网站设置]]

### 2. 首页模块与主题

首页模块控制前台内容区块、顺序、标题、数量和启用状态。管理员可以使用预设、调整排序并预览。保存后由首页构建器按配置组合模块。模块依赖的文章或分类为空时，前台可能隐藏该区块。修改后检查桌面、移动端和多语言文本。

主题切换决定前台布局、颜色和组件风格。主题复刻流程包含参考分析、隔离预览、迭代、合规检查、审查包和发布。预览环境与正式主题隔离，发布前确认没有外部密钥、危险脚本、不可访问资源和版权问题。主题归档用于恢复历史包，正式发布仍应备份。

### 3. SEO 与机器可读内容

前台输出文章、分类、关于、归档、站点地图、Open Graph 和 Schema。文章标题、摘要、规范地址、发布时间、作者和图片共同影响展示。`sitemap` 帮助搜索引擎发现页面，`llms.txt` 和相关发现文件帮助生成式系统理解站点范围。生成文件后需要确认 URL 使用公开站点域名，并与当前发布内容一致。

### 4. 线索表单

表单设置用于创建前台咨询或线索表单，配置名称、字段、必填项和启用状态。前台只展示启用且符合当前页面配置的表单。字段变更后检查旧提交兼容性。提交接口包含验证、频率限制和安全处理。

线索管理用于查看提交、筛选状态、进入详情、更新处理结果和导出。线索可能包含姓名、联系方式和需求，访问和导出都应遵循最小权限。处理状态用于团队协作，更新时填写必要说明。需要删除或长期保存时遵循组织的数据留存政策。

相关入口：[[route:admin.lead-forms.index|进入表单设置]]
相关入口：[[route:admin.leads.index|进入线索管理]]

## 十一、AI 配置、模型与提示词

### 1. AI 配置器

AI 配置器集中展示 Provider、对话模型、Embedding 模型和提示词状态。管理员先建立 Provider 或模型 API，再把具体模型绑定到用途。系统支持 OpenAI 兼容接口和部分原生接口。API 地址、模型标识、密钥和模型类型必须与服务商文档一致。

功能入口：[[route:admin.ai.configurator|进入 AI 配置器]]
相关入口：[[route:admin.ai-models.index|管理 AI 模型]]
相关入口：[[route:admin.ai-prompts|管理提示词]]

### 2. 对话模型与 Embedding 模型

对话模型用于文章生成、标题生成、AI 工作台和质量检查。Embedding 模型用于知识向量。模型记录包含名称、版本、接口、模型 ID、类型、状态、最大输出和就绪信息。默认模型决定没有显式指定时的选择，故障转移允许主模型失败后尝试备用模型。

连接检测会发送受控探测并记录成功、延迟和错误。检测成功后仍要确认额度、上下文和输出限制适合业务。AI 工作台要求可用对话模型；知识强制真实向量刷新要求可用 Embedding 模型。模型停用前检查任务、提示词、质检和默认绑定。

OpenAI 兼容接口通常需要基础 API URL、密钥和模型 ID。URL 不应重复拼接资源路径。Gemini 等原生接口使用对应 Provider 规则。401 或 403 多与密钥权限有关；404 多与 URL 或模型 ID 有关；429 多与额度和频率有关；超时应检查网络、模型响应速度和输出上限。

### 3. 提示词

提示词决定文章结构、语气、约束和输出格式。系统提示词用于通用生成，专用提示词用于标题、质检或其他能力。修改提示词会影响后续运行，已经生成的文章不会自动变化。发布高影响提示词前，应使用小样本对比并记录版本。

提示词应明确目标、输入、事实边界、格式和失败行为。需要结构化输出时，配合本地结果校验，不能只依赖模型承诺。把密钥、个人信息或内部提示词放入用户可编辑内容会扩大泄露风险。

### 4. 模型不可用排查

AI 工作台或生成任务提示模型不可用时，依次检查：运行时功能是否启用；是否存在 active 对话模型；模型是否通过所需就绪策略；API URL 和密钥是否有效；服务商额度是否充足；出站网络是否允许；超时和最大输出是否合理；备用模型是否配置。修复后先执行连接检测，再重试小请求。

## 十二、用户、权限、安全与审计

### 1. 个人账号与管理员

个人资料允许修改显示信息和密码。密码更新需要当前身份和安全校验。管理员管理由超级管理员创建、编辑、启停和分配角色。停用账号会阻止后续登录，已有会话和浏览器客户端应同时审查。

功能入口：[[route:admin.account.show|进入个人账号]]
相关入口：[[route:admin.admin-users.index|管理后台用户]]

### 2. API Token

API Token 用于 CLI 或受控集成。创建时选择最小 scope，令牌明文只在创建时展示，服务端保存安全摘要。调用 API 时还要通过版本和权限检查。令牌不再使用、人员变化或疑似泄露时立即撤销。日志和知识文档不能保存完整令牌。

写接口使用参数校验、scope、幂等键和审计。客户端遇到 401 时检查令牌；403 检查 scope 和角色；409 检查资源状态或幂等冲突；422 检查字段错误。API 返回的错误代码适合程序判断，消息用于管理员理解。

### 3. 安全设置与操作日志

安全设置包含密码、敏感词和其他后台安全规则。修改会影响全局，应先评估现有内容和用户。敏感词规则更新后，相关风险结果可能需要重检。

操作日志记录管理员、动作、目标、时间和必要摘要，用于追踪高风险变更。日志避免保存密钥、完整个人资料和大段正文。排查“谁修改了配置”时，先按时间和管理员筛选，再结合目标对象状态。日志反映系统记录的动作，外部平台最终状态还需到分发或人工发布记录确认。

相关入口：[[route:admin.security-settings.index|进入安全设置]]
相关入口：[[route:admin.admin-activity-logs|查看操作日志]]

### 4. 出站与文件安全

所有服务端外部请求应经过安全客户端，限制协议、主机、端口、重定向和响应大小，防止 SSRF。受管图片和导入文件使用固定存储根、生成文件名、真实 MIME 校验和路径守卫。浏览器输入的路径、URL 和 MIME 都不能直接信任。

## 十三、系统更新、部署与运行维护

### 1. 系统更新

系统更新包含检查版本、下载发布包、校验哈希、生成计划、风险预检、备份、执行手工命令、验证和回滚。只有具备权限的管理员可以操作。更新计划会根据代码变化列出 Composer、前端构建、迁移、系统知识同步、缓存清理和队列重启等步骤。

功能入口：[[route:admin.system-updates.index|进入系统更新]]

更新前确认数据库和文件备份可恢复、磁盘充足、队列状态可控、发布包来源可信。执行迁移后不要随意回滚包含业务数据的新表，代码回滚通常保留向后兼容表和数据。每个必需命令完成后在计划中标记并执行验证。失败时保留运行记录和备份，按故障阶段选择继续、修复或回滚代码。

### 2. 首次安装与升级

生产 `init` 服务先迁移，再执行 `geoflow:install`。首次空库会创建必要初始数据，已有业务数据库只记录安装状态并保护用户配置。AI 工作台系统知识由显式幂等同步命令创建或安全升级。管理员已经自定义正文时，升级不会自动覆盖。

Docker 常驻服务包括应用、队列、调度器、实时服务和代理。常驻服务不应在每次启动时重复写入可编辑默认数据。升级后检查应用健康、队列、调度器、数据库迁移、缓存和前端资源。

### 3. 队列、Horizon、Redis 与 Reverb

Redis 提供缓存、队列和实时协作基础。Horizon 管理队列进程、平衡和失败任务。Scheduler 触发周期任务，Reverb 提供实时事件。页面生成进度或任务状态不更新时，分别检查这些服务和代理配置。

队列 `retry_after` 必须大于任务超时，避免同一工作重复执行。外部请求使用退避和幂等。失败任务恢复前先修复根因。重启队列会让当前 Worker 在安全点退出并加载新代码，仍需观察长任务是否完成。

### 4. 常见部署故障

页面 500 时检查应用日志、配置缓存、数据库连接和迁移。静态资源旧或缺失时重新构建并检查 Vite 清单、浏览器缓存和代理。后台登录循环时检查会话、Cookie 域、HTTPS 和代理头。托管站点失败时检查根域、证书、Nginx 和站点档案。知识检索为空时检查系统知识绑定、正文、切片状态和知识队列。

## 十四、API、CLI 与扩展能力

### 1. API v1

API v1 提供认证、目录、任务、运行、素材和文章等受控接口。请求使用版本前缀、Token scope、分页和统一错误结构。写请求应提供幂等键。客户端不能根据错误消息文本判断业务，应优先使用状态码和错误代码。

分页响应包含当前页、每页数量、总数和总页数。批量操作需要限制数量。API 只返回授权字段，敏感配置保持隐藏。修改或删除素材时，服务层执行与后台相同的引用检查和系统知识保护。

### 2. GEOWorkFlow CLI

GEOWorkFlow CLI 通过 API 完成登录、目录、任务、运行、素材和文章操作。首次使用配置服务地址和 Token，随后根据命令帮助提供参数。CLI 不应绕过服务端验证，也不直接连接数据库。命令失败时查看退出码、错误代码和字段信息。

素材命令可以列出、查看、创建、更新和删除普通知识库。AI 工作台系统知识库的删除会返回冲突错误。系统知识同步属于服务器管理命令，需要在部署环境使用 Artisan 执行。

### 3. GEOWorkFlow Agent 与能力模式

GEOWorkFlow Agent 可以根据授权工作在查询、内容、任务、分发或系统说明等模式。每种能力有明确输入、风险、成熟度和权限。只读能力可以返回实时数据；写入能力需要参数校验、审批、幂等和审计。系统知识为能力说明提供事实，不能改变能力注册表。

## 十五、通用排查方法与回答原则

### 1. 通用排查顺序

遇到问题时使用以下顺序可以降低误判：

1. 确认当前页面、对象 ID、筛选条件、时间范围和账号权限。
2. 查看页面的状态、错误提示、最近更新时间和健康信息。
3. 检查上游依赖，例如模型、内容资产、渠道、队列、数据库和网络。
4. 查看对应运行记录、失败记录和管理员操作日志。
5. 修复根因后使用页面提供的重试、恢复、重建或重新检测动作。
6. 回到结果页面读取最终状态，外部写入还要核对目标系统。

### 2. 数据为空

数据为空先检查筛选和时间，再确认是否存在产生数据的上游活动。分析页为空可能来自没有访问或任务；文章为空可能来自任务未运行；知识切片为空可能来自同步未执行；分发为空可能来自文章没有进入渠道；线索为空可能来自表单未启用或没有提交。不要通过直接写数据库制造状态。

### 3. 状态长时间不变

异步状态长时间不变时，检查 Scheduler、队列、Worker、Horizon、锁和租约。确认工作是否仍在运行，再决定等待、恢复或重试。重复提交可能形成并发冲突。系统提供恢复命令时，应使用幂等命令并保留原运行记录。

### 4. 权限与入口

回答中的站内入口只展示当前管理员有权访问的稳定 GET 页面。状态变更仍需在目标页面由管理员确认。页面缺失时，检查当前版本是否包含该功能、后台 UI V3 是否启用、路由是否存在和账号权限是否满足。

### 5. 安全与隐私

排查材料可以包含错误代码、状态和必要对象 ID，不能包含完整 API Key、Token、密码、客户资料、线索个人信息或服务器绝对路径。截图用于帮助知识时应使用安全样例数据，并完成隐私检查。外部链接和上传文件始终经过验证。

### 6. 推荐工作习惯

高风险改动先做小范围验证，正式执行前备份和预览，执行后从结果页面读回。把稳定业务规则放入任务、提示词和知识库，把一次性判断留在运行记录。持续观察数据中心和失败记录，按版本维护系统知识，可以让 AI 工作台长期提供准确指南。
