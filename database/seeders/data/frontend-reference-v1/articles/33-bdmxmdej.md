在 GEOWorkFlow 中创建任务并不复杂，但启动前需要先满足最小配置依赖并完成小样本测试。一次完整的 GEOWorkFlow 任务创建，实际上是把标题库、知识素材、模型、生成参数与发布范围组合成一个可执行的工作流。下面从最小依赖、创建步骤、测试与发布配置几个方面说明具体做法。

## 任务创建前需要准备什么
后台“快速开始”给出了清晰的启动顺序。创建任务前，至少需要完成两项准备：
1. **配置 API 模型**：在后台添加至少一个可用的 chat 模型。如果任务需要基于知识库进行 RAG（检索增强生成）召回，还需要额外添加一个 embedding 模型，并选择适合业务资料的知识库切片策略。

## 如何新建任务并设置最小参数
进入后台任务管理页面后，新建任务的核心操作如下：
1. 选择一个已配置好的标题库，确定本次任务要覆盖的内容主题。
2. 关联所需的素材，包括知识库、图片库和作者库。
3. 选择任务要调用的 chat 模型。
4. 设置生成数量与发布频率，用于控制内容产出节奏。
5. 选定发布范围，决定生成内容最终出现在哪些位置。

## 用小样本测试验证链路完整性
生产环境直接大批量运行之前，需要先创建一个小任务验证完整链路。验证重点包括：
- 文章能否正常生成并进入审核队列。
- 审核流程是否完整。
- 前台输出是否正常，SEO 结构化数据和 Schema 标记是否正确。
- 若启用了分发，目标站点是否成功接收内容。
小样本测试规模控制在 3 到 5 篇即可。只有当生成、审核、发布和分发全链路都跑通后，才适合逐步扩大任务量和渠道分发范围。

## 配置发布与分发范围
GEOWorkFlow 创建或编辑任务时，可选择三种发布范围：
| 发布范围 | 说明 |
| --- | --- |
| 本地和渠道站点同时发布 | 文章在 GEOWorkFlow 本地公开，同时进入已选渠道的分发队列。 |
| 仅发布到渠道站点 | 本地保留管理副本，前台不公开，目标渠道生成公开内容。 |
这个设置直接决定了内容是否被推送到外部站点，以及本地前台是否展示。

## 启动前检查清单
在正式启动 GEOWorkFlow 任务之前，建议逐项确认以下条件：
- API 模型已添加且可用，embedding 模型按需配置。
- 知识库内容真实且已完成切片。
- 标题库、图片库和作者信息已录入。
- 已使用小任务完成全链路测试。
- 发布范围和分发渠道已按实际需求配置。
- 如需自动发布，队列和 Worker 处于正常运行状态。
