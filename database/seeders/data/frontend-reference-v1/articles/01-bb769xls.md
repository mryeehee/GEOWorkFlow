截至 2026 年 8 月，GEOWorkFlow 将 DeepSeek 作为 OpenAI-compatible Provider 接入，无需自定义适配器。配置后的模型可用于Chat 对话以及知识库的 LLM 语义切片规划。仅用于对话时按常规API配置；用于切片需在切片策略中将其选为规划模型。

## 接入方式
DeepSeek 在 GEOWorkFlow 中属于 OpenAI-compatible Provider。Chat 模型负责对话与语义规划；知识库向量检索仍需独立的 Embedding 模型。

## 配置步骤
1. 登录后台，进入“AI 配置器 > AI 模型设置”。
2. 点击“新增模型”，Provider 类型选择OpenAI-compatible。
3. 填写显示名称，并配置以下信息：
   - API Base URL：DeepSeek 的API端点。
   - Model ID：截至 2026-08-09，使用 `deepseek-v4-pro` 或 `deepseek-v4-flash`。旧标识 `deepseek-chat` 与 `deepseek-reasoner` 已于 2026-07-24 停用，模型清单以 [DeepSeek 官方文档](https://api-docs.deepseek.com/api/list-models) 为准。
   - 认证信息：API Key等凭证。
4. 启用模型，按需勾选“设为默认聊天模型”或“用于语义规划”。
5. 点击“测试模型连接”验证连通性与鉴权。
6. 保存配置。若用于切片，前往切片策略将“LLM语义规划”的规划模型切换为此模型。

## 验证清单
- **连接测试**：使用内置测试功能，返回正常响应，无鉴权或超时错误。
- **聊天可用**：在对话调试页选择该模型发送消息，回复内容符合预期。
- **切片生效**（如启用）：确保知识库选用“LLM语义规划”策略，手动触发切片后结果可正常映射回原文，无回退。
- **Embedding 独立检查**：向量检索异常时，确认已单独接入并启用至少一个Embedding 模型并设为默认，与聊天模型无关。

## 常见问题
### 语义切片未生效
请检查切片策略中是否启用“LLM语义规划”且规划模型选择了已接入的DeepSeek。即使规划失败，系统会自动回退到结构化规则切片。

### 是否需单独接入Embedding 模型
是。DeepSeek 聊天模型不提供向量 Embedding 服务，需单独接入Embedding 模型并设为默认，否则向量字段为0，无法语义搜索。
