GEOWorkFlow 知识库有切片但向量为 0，通常说明 Embedding 模型没有成功写入向量索引。根据官方资料，问题根源基本出现在模型配置、连接状态或默认标识上。下文依据 GEOWorkFlow 当前版本机制，整理一套可核验的 **GEOWorkFlow 向量化排查** 步骤。

## 为什么有切片，向量却为 0？
在 GEOWorkFlow 里，切片是把上传的文档按结构化规则或 LLM 规划拆分成可检索片段，向量则是由 Embedding 模型把这些片段转成高维数值表示，供语义召回使用。两者是独立步骤。如果知识库预览显示切片正常但向量数为 0，意味着文档已拆分完毕，Embedding 写入环节被中断或从未执行。

## Embedding 模型配置检查
排查的第一步是进入 `AI 配置器 > AI 模型设置`，逐项核对以下四个条件：
1. **模型类型是否为 `embedding`**：模型列表中必须存在一条记录，其类型显示为 `embedding`，不能用聊天模型代替。
2. **API Key 有效且权限足够**：该 Key 对应的接口必须支持 `/v1/embeddings` 端点，且配额未耗尽。

## 验证接口连通性
即使配置项看起来正确，也需通过模型设置页面的“测试连接”按钮验证实际连通性。常见失败原因包括：
- 填错 Base URL 导致 404
- 代理或网络策略拦截 Embedding 请求
- Provider 的 Embedding 接口暂时不可用
测试成功后，再回到知识库管理页，对目标知识库执行一次“刷新向量”操作，观察向量数是否从 0 跳变为正数。

## 确认切片策略不会阻断向量生成
GEOWorkFlow 支持两种切片策略：**结构化规则切片**与 **LLM 语义规划**。如果选择了 LLM 语义规划，需要额外检查：
- 是否已配置了可用的聊天模型来执行规划
- 若规划失败（超时、JSON 不合法等），系统会自动回退到规则切片
回退不影响切片生成，但仍需要前述 Embedding 模型就位才能生成向量。

## 检查清单
通过以下清单可快速定位绝大多数“切片有、向量为 0”的问题：
- 模型类型一栏是否存在 `embedding` 模型
- 该模型 API Key 有效且未过期
- 接口地址可正确响应 embeddings 请求
- 该模型已被设为系统默认 Embedding 模型
- 已点击知识库的“刷新向量”并等待任务完成
- 若使用语义规划，确认规划模型可用或系统已成功回退
