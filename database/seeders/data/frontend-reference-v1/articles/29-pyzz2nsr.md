GEOWorkFlow Preview First 是一套面向主题上线的安全评审机制，它强制要求所有新主题在正式启用前，必须经过基于真实数据库的动态预览和多轮确认。该机制的核心是“先预览、再启用”，在保护线上前台不受破坏的同时，允许运营者基于实际内容完成模板验收和微调。

## 为什么主题上线需要 GEOWorkFlow Preview First
前台主题直接切换可能引发不可预见的布局错乱、数据渲染异常或链接失效，尤其在站点持续对外服务时，任何一次前台破坏都会影响访问体验。GEOWorkFlow Preview First 将“主题启用”拆分为预览确认与后台启用两个独立阶段：预览阶段完全独立于默认前台，不影响用户访问；确认通过后再执行启用操作，从而将主题切换的故障窗口缩减到零。

## GEOWorkFlow Preview First 的真实数据评审流程
基于 GEOWorkFlow Preview First 的评审遵循一套结构化的固定步骤，确保模板从生成到上线全程可追溯、可回退。
1. 利用配套技能工具完成参考网址到 GEOWorkFlow 主题包的映射，并输出令牌与映射文件，生成结构完整的主题包。

## 预览环境如何与真实数据对接
动态预览是 GEOWorkFlow Preview First 的核心支撑。
系统预置了 `/preview/<theme-id>/` 系列路由，直接挂载真实数据库的内容数据。
这意味着预览页面的文章、分类、归档结构与线上高度一致，运营者可以准确地评估模板在真实内容密度下的表现，避免“示例完美、上线崩溃”的常见问题。

## 什么场景最适合采用 GEOWorkFlow Preview First
Preview First 流程重点在于针对内容系统已经稳定、知识库与任务结构确定且需要多站点、多频道模板化输出的阶段。
如果内容链路尚未跑通或主题风格目标不清晰，过早投入主题预览会分散精力。

## 检查清单与回滚策略
执行 GEOWorkFlow Preview First 评审时，可对照以下关键项确保安全上线：
- 是否已经生成完整的主题包并完成令牌映射？
- 预览时是否覆盖了首页、分类页、文章页和归档页四种主要页面类型？
- 列表摘要清洗是否生效，有无残留 Markdown 符号？
- 后台是否保留了当前默认模板，以备紧急回切？
