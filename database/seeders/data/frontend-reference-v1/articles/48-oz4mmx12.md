GEOWorkFlow 的知识切片设计直接影响检索召回质量和证据可信度。高质量切片需要把 **标题、章节路径和元数据** 作为切片的固定骨架，确保每一次召回都能溯源上下文和治理信息。本文基于 GEOWorkFlow 当前规则，说明标题、章节路径与元数据的规范以及落地方法。

## 为什么标题和章节路径是切片骨架
GEOWorkFlow 默认采用结构化规则切片，它会识别 Markdown 标题层级并抽取章节路径，同时为每个片段生成对应的切片标题。在设计时坚持保留完整 **标题与章节路径**，可以获得三重收益：
- **提升召回精度**：混合召回算法会把标题和章节路径匹配作为重要加权信号，避免纯向量检索遗漏精确术语。

## GEOWorkFlow 知识切片设计的元数据规范
**元数据**是描述切片属性的一组字段，GEOWorkFlow 要求每条切片在入库时必须携带治理信息，否则高风险或未审核的资料将无法进入生成上下文。规范化的元数据字段如下：
| 元数据字段 | 说明 | 使用场景 |
|---|---|---|
| 来源 | 文档名称或 URL | 建立可追溯的知识地图 |
| 资料时间 | 内容生效或更新时间 | 判断信息时效 |
| 业务线 | 知识所属产品或团队 | 缩小召回范围 |
| 风险等级 | low、medium 或 high | 控制高风险资料进入上下文 |
| 审核状态 | 未审核或已审核 | 优先采用已确认资料 |

## 如何设计高质量知识切片
结合标题、章节路径和元数据，建议按以下步骤完成切片设计：
1. **整理资料结构**：用 Markdown 重写或清洗原文，确保每个知识单元有明确标题和章节归属。
2. **补全元数据**：在知识库编辑页填写来源、业务线、资料时间、风险等级和审核状态。
3. **更新切片与向量**：保存资料后更新切片，并使用默认 Embedding 模型完成向量化。
4. **检查切片信息**：在切片列表逐一确认：标题是否可读，章节路径是否完整，元数据是否准确。

## 检查清单
- [ ] 原始资料是否使用了标准 Markdown 标题层级？
- [ ] 所有切片是否都继承了正确的 **章节路径** 和可读的 **切片标题**？
- [ ] 每条知识的元数据（来源、时间、业务线、风险、审核状态）是否完整无缺？
- [ ] 是否已保存并生成切片，再启用默认 embedding 模型？
- [ ] 在任务生成中检查证据编号 K1、K2 等，是否携带标题和章节信息？

## 常见问题
**Q1：切片标题和章节路径可以手动修改吗？**
系统会自动抽取，如果原结构不规范，建议先在“AI 知识库中枢”重新编辑资料并更新切片。手动修改标题可能会让召回权重计算偏离原始语义。
**Q2：元数据填错了怎么办？**
在知识库编辑页面更新元数据后，再次点击“更新切片”并重新向量化，即可让修改生效。已审核资料的修订也要重新标记审核状态，避免旧缓存干扰。
