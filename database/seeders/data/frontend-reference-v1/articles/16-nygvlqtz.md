GEOWorkFlow 多站点分发通过发布范围、渠道配置与异步队列，把同一篇已审核文章同步到本地站点、GEOWorkFlow Agent 站点或 WordPress。首次配置应先确定本地是否公开，再用单一渠道完成连接、发布、日志和重试验证。

## 发布范围
发布范围决定文章的展示位置。同时发布到本地与渠道时，文章在 GEOWorkFlow 本地及所有已选远端渠道均公开。仅发布到渠道站点时，本地仅保留管理副本，不对外展示。仅发布到本站时不可勾选分发渠道，文章只在本地公开。先明确本地公开需求，再决定是否启用多渠道同步。

## 支持渠道
多站点分发支持两类渠道。GEOWorkFlow Agent 适用于新建轻量 PHP 站点，通过预配置站点包生成静态首页、详情页、sitemap 和 llms.txt，并可同步图片与远端设置。WordPress REST 用于已有 WordPress 站点，通过 Application Password 实现文章发布、更新与删除，同时管理媒体文件、分类及标签。

## 添加分发渠道
以 GEOWorkFlow Agent 为例，新建渠道并填写基础信息后，系统生成密钥 ID 与明文。下载的站点包含 Agent 地址、密钥、主题、静态资源配置以及 Apache 的 .htaccess、Nginx rewrite 规则。将站点包上传至目标服务器完成部署，回到 GEOWorkFlow 验证远端连通性并启用渠道。WordPress REST 渠道需先在 WordPress 生成 Application Password，填入 GEOWorkFlow 渠道配置，测试连接后保存。首次配置建议只接入一个目标站点，验证通过后再增加渠道，防止分发队列堆积。

## 分发队列与追踪
任务创建并选择渠道后，相关文章进入分发队列，按渠道逐一推送。日志可追踪每次推送状态，远端生成失败时能查看错误详情，支持对单篇文章重新触发分发，无需重复执行整个任务。人工发布工作台独立管理需手动完成的工单，不自动访问外部网站，不保存第三方凭证，用于无法通过 API 直连的平台，由运营人员手工复制内容并回填结果。

## 配置检查清单
完成配置后逐项确认：明确一种发布范围，避免本地与渠道内容冲突。渠道类型与目标站点技术环境匹配，静态站点选 Agent，已有 WordPress 站点选 REST。GEOWorkFlow Agent 站点包已正确部署且密钥匹配。至少完成一次测试分发，日志无异常。若使用人工发布，需建立对应的发布身份和工单执行人。
