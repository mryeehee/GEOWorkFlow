在 GEOWorkFlow 正式上线前，需要对环境依赖、队列调度、安全配置、存储备份与前端输出做系统性核查，确保内容生成、审核、发布全链路闭环稳定。这份清单结合官方部署检查与健康检查脚本，汇总成可直接执行的上线前验证步骤。

## 环境与运行依赖是否就绪
首先检查服务器基础环境与容器服务。PHP 版本须符合当前仓库要求，核心扩展如 `pdo_pgsql` 和 `curl` 已启用；PostgreSQL、Redis 均能正常连接。如果采用 Docker 部署，还应确认 `docker compose` 可以启动，且 `app`、`queue`、`scheduler`、`postgres`、`redis` 等容器网络互通。

## 队列与调度进程是否正常
GEOWorkFlow 的后台内容生成、Embedding、发布等任务依赖队列与调度系统。上线前必须保证 Worker 进程持续监听队列，且 Scheduler 按预期触发定时任务。健康检查脚本的输出可以帮助快速定位队列未启动或 Redis 连接失败的问题。

## 安全设置是否已加固
安全项可以从以下几个层面逐条确认：
- 默认管理员密码在首次登录后已修改
- 后台入口路径 `ADMIN_BASE_PATH` 已定制，避免使用过于可预测的路径
- 生产环境关闭调试模式：`APP_DEBUG=false`
- 生产环境关闭浏览器日志监听：`BOOST_BROWSER_LOGS_WATCHER=false`
- PostgreSQL 和 Redis 端口不对外暴露

## 存储路径与备份策略是否到位
GEOWorkFlow 的生产数据包括 PostgreSQL 数据库和上传文件，都需要定期备份。应至少确保：
- 数据库备份策略已设定，例如通过 `pg_dump` 定时导出并同步到异地
- 上传文件目录（通常位于 `storage/app/public`）已纳入备份流程
- 备份恢复流程经过一次实际演练
