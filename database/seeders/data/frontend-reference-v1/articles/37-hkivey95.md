在 GEOWorkFlow 里，内容从生成到对外呈现始终被组织为一组明确的状态：**草稿、审核、发布、回收站**。这四种状态定义了文章在系统内的生命周期，也是内容团队协作和风险控制的基础。GEOWorkFlow 内容状态的管理重点在于在任务调度、分发管理和前台渲染等环节中直接生效的系统能力。

## 四种内容状态的定义与流转
GEOWorkFlow 为每篇文章维护一个生命周期状态，该状态决定文章在后台的可见性、是否可发布到前台，以及是否进入分发队列。状态流转遵循固定路径：
1. Worker 执行 AI 生成后，文章首先进入**草稿**状态。
2. 开启审核时，草稿保持待审核；关闭审核时，任务可按配置自动通过。
3. 审核通过后执行发布，文章进入**已发布**状态并获得公开时间。
4. 已发布文章可移入**回收站**，作为软删除管理。

## 草稿：未校验的初始生成结果
草稿是文章生成后的第一站。处于草稿状态的文章仅在后端可见，不会出现在前台页面，也不会触发分发动作。
在这个阶段，编辑人员可以：
- 检查 AI 生成内容的事实准确性和提示词遵守情况。
- 修正 Markdown 渲染异常或结构性错误。
- 补充 SEO 元信息、作者和分类等字段。

## 审核：手动确认的质量门槛
审核状态表示文章正在等待人工审阅。当文章处于审核中，任何前台访问或分发接口都不会暴露该内容，从而确保只有通过审查的文章才能对外发布。
审核阶段关注的重点通常包括：
- 内容是否源自知识库且论据可核验。
- 是否满足目标站点或栏目的内容规范。
- SEO 字段和 Open Graph 标记是否完整。

## 已发布与回收站：可见性控制与软删除
已发布状态意味着文章已经在授权范围内正式上线。在 GEOWorkFlow 本地前台，文章可通过 GFM Markdown 渲染为带样式页面，并附带结构化数据（如 Schema）；在目标渠道站点，Agent 包或 REST API 会同步页面、媒体和分类。回收站中的文章不会继续公开；需要恢复时先回到可编辑状态，再重新审核和发布。

## 内容状态对比一览
| 状态 | 后台可见 | 前台公开 | 可分发 | 关键操作 |
| :--- | :---: | :---: | :---: | :--- |
| 草稿 | ✅ | ❌ | ❌ | 编辑、提交审核、直接发布（无审核时） |
| 审核 | ✅ | ❌ | ❌ | 通过发布、退回草稿 |
| 已发布 | ✅ | ✅ | ✅ | 移入回收站、编辑更新并重发 |
| 回收站 | ✅ | ❌ | ❌ | 恢复或按权限永久处理 |
