GEOWorkFlow 快速上手可按部署系统、配置模型、准备素材、创建小任务、检查草稿五步完成。首次验证建议只生成 1 至 2 篇草稿，确认完整链路后再扩大规模。

## 系统准备

按照 GitHub Wiki 部署指南完成代码获取、依赖安装和服务启动。成功后通过浏览器访问后台地址，使用初始化账号登录。仪表盘“快速开始”引导区是验证系统就绪的核心入口，只需依次完成其中三项配置。

## 配置 API 模型

至少添加一个 Chat 模型，用于大纲生成和正文撰写。进入“模型管理”，添加模型时填写提供商、名称和访问密钥并确认可用。需知识库向量化召回时再补充 Embedding 模型。保存后使用测试功能发送提示词，确认返回正常。

## 搭建基础素材库

第一轮验证重点搭建标题库和知识库。在标题库录入 3 至 5 个标题，在知识库创建知识库并上传产品说明、FAQ 等文本，便于验证召回准确性。按需添加作者和默认图片，素材库不能为空，否则任务会因缺少参数而失败。若启用知识库 RAG，配置合适的切片策略。

## 创建任务并生成草稿

素材就绪后进入“任务管理”新建任务，关联标题库、知识库、图片库和作者库。指定生成模型与生成数量，建议每次 1 至 2 篇。为安全关闭自动发布，将文章最终状态设为“草稿”或“进入审核”。提交后系统推送到队列，Worker 执行生成，完成后文章出现在“内容草稿”列表。检查草稿结构、知识库引用和元信息，确认链路走通。

## 验证清单与常见问题

验证清单：后台仪表盘正常访问；至少一个 Chat 模型配置并测试通过；标题库和知识库已导入可验证内容；已创建任务并关联模型与素材库；任务执行后草稿列表存在生成文章；如需 RAG 召回，已添加 Embedding 模型且切片策略生效。

快速开始中看不到模型或素材库选项，检查账号权限和功能导航启用状态，仍不可见则确认后台服务全部启动。任务创建后长时间无草稿，多为队列或 Worker 未运行，可查看系统日志，按部署指南重启调度服务，并确认模型可用、素材库有有效内容。
