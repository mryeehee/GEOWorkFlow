GEOWorkFlow 以 GitHub Flavored Markdown 作为文章正文标准，支持标题、列表、链接、表格、任务列表、代码块等常用语法，并由主题控制最终视觉样式。

## 正文语法支持

GEOWorkFlow 正文采用 GitHub Flavored Markdown 作为书写与渲染规范。前端展示时，符合 GFM 语法的正文会被渲染为富文本，列表页和卡片则自动清洗符号以保证摘要可读性。内容团队按 GFM 约定书写即可获得跨主题的一致排版。支持范围以当前主题渲染结果为准。支持的常见元素包括多级标题（`#` 至 `######`）、无序和有序列表、链接、粗体、斜体、行内代码、删除线、表格、任务列表、围栏代码块（可标注语言）以及自动链接。书写时直接遵守这些规则，系统集成的 GFM 解析器会完成渲染，字体和间距等视觉细节由主题包控制，结构化语义在所有模板下保持一致。

## 摘要清洗与模板适配

文章卡片会自动对摘要执行 Markdown 符号清洗，避免出现 `#`、`*`、`[` 等原始标记。清洗过程由系统自动执行，无需手动干预。如果摘要依然残留格式符号，通常与主题模板的摘要截取方法有关，应调整主题 `tokens.json` 中的摘要字段配置，而不是修改正文。

## 主题渲染控制

网站设置支持主题预览和启用，每个主题包使用独立模板定义 GFM 正文的输出样式。已公开的样板主题 `qiaomu-editorial-20260418` 可作为定制排版风格的参考，例如调整标题间距、代码块底色和表格边框。修改主题不会影响 GFM 语义结构。

## 书写与编辑要点

编辑前务必确认内容编辑区接受 GFM 语法，不要混入富文本标签。不推荐在正文中直接嵌入 HTML。迁移旧文章时，图片路径可能发生变更，系统会进行路径兼容，但前提是已正确执行 `php artisan storage:link`。

## 发布后检查

发布后检查页面渲染效果，必要时在网站设置中调整主题选择。卡片摘要异常时，优先排查主题的摘要处理逻辑，而非修改正文。建议同时检查桌面端与移动端表现，确认标题层级、表格横向滚动、代码换行和链接状态都符合阅读预期。
