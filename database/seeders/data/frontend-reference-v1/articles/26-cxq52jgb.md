GEOWorkFlow 主题工作流遵循“先预览，后启用”的安全原则：先用主题包定义前台展示层，再通过动态预览路由在真实数据上验证效果，最后在后台一键启用或回退。这让模板化成为可持续迭代的站点外观管理方式，并降低一次性替换的上线风险。

## 什么是主题包
主题包只负责前台展示层，包含页头、页尾、首页、分类页、文章页、归档页以及样式与视觉 token，不涉及后台逻辑或内容生产流程。它被设计成独立且可替换的单元，避免对内容系统造成侵入性影响。

## 主题工作流的完整步骤
推荐的主题化流程共有五个阶段：
1. 确定参考站点或目标风格
2. 使用仓库内置统一 Skill `$geoflow` 进行模块映射和 token 提取；旧标识 `yao-geoflow-template` 已并入统一 Skill
3. 生成主题包并按 `themes/<theme-id>` 结构放置
4. 先走动态预览，基于真实数据检查首页、分类页、文章页、归档页效果
5. 预览确认后，在后台“网站设置”中启用

## 动态预览如何验证效果
系统为每个主题包提供了专用预览路由：
- `/preview/<theme-id>/`：首页
- `/preview/<theme-id>/category/<slug>`：分类页
- `/preview/<theme-id>/article/<slug>`：文章页
- `/preview/<theme-id>/archive`：归档页

## 如何安全启用与回退
在后台“网站设置”中，管理员可以查看当前启用的模板，预览各页面，也可以随时切回默认前台或启用新主题包。GEOWorkFlow 建议的启用原则是：
- 预览全部通过后再启用
- 启用前保留默认模板作为备份
- 出现版面或显示问题时优先回切默认模板
由于主题包与内容生产解耦，回退操作不会影响文章队列、分发状态或远端同步。

## 什么时候适合启动主题化
主题工作流不是越早执行越好。根据官方推荐，适合启动的条件是：内容链路已经跑通，知识库和任务结构稳定，前台有明确的风格目标，或者需要多站点、多频道同时输出不同外观。如果内容本身还不稳定，过度投入主题层反而会增加维护负担。
核心原则可以概括为：模板应该服务于内容系统，并保持内容系统的独立性。
