GEOWorkFlow 的通用 HTTP API 渠道用于将内容自动分发到任意支持 HTTP 接口的第三方内容系统。你只需要在后台创建一个通用 API 渠道，在对应动作下配置好接口路径、鉴权方式和响应映射，GEOWorkFlow 就会沿用现有的分发队列、重试机制和日志记录向目标系统推送内容。

## 通用 HTTP API 渠道支持哪些操作动作？
GEOWorkFlow 通用 HTTP API 渠道把内容生命周期拆分为五个可独立配置的动作，每个动作可以指定不同的 HTTP 方法和路径，并决定是否向目标系统发送请求：
- **健康检查**：测试目标接口是否可用，通常配置 `GET` 请求。
- **发布**：首次把文章推送到第三方系统，一般使用 `POST` 或 `PUT`。
- **站点设置同步**：与站点级别的配置关联，用于同步全局信息。

## 如何配置认证方式？
通用 HTTP API 渠道提供多种鉴权选项，适应不同第三方系统的安全要求：
| 认证方式 | 适用场景 |
| --- | --- |
| 无鉴权 | 内部系统或测试环境 |
| Bearer Token | OAuth 2.0 或简单令牌鉴权 |
| Basic Auth | 通过用户名和密码的 HTTP 基本认证 |

## 响应字段映射和成功判断怎么设置？
为了让 GEOWorkFlow 确认文章在第三方系统里创建或更新成功，需要配置响应映射和成功状态码：
- **成功状态码**：默认 `200` 视为成功，可按目标系统实际返回设置，如 `201`。
- **Payload 包装**：有时目标接口要求请求体套一层固定结构，你可以通过 Payload 模板把内容包装成目标系统需要的格式。

## 通用 HTTP API 渠道的分发流程有何特点？
通用 HTTP API 渠道完全复用 GEOWorkFlow 现有的分发体系：
- **分发队列与重试**：所有分发任务进入统一队列，失败后自动重试，重试次数可配。
- **日志记录**：每次请求的完整调用信息会记录在分发日志中，包括请求体、响应状态和错误信息，便于排查问题。

## 检查清单
- 确认第三方系统提供了 REST 风格的创建、更新、删除接口。
- 在 GEOWorkFlow 后台依次填写健康检查、发布、更新、删除、站点设置同步的 HTTP 方法和路径。
- 根据目标系统要求选择对应的鉴权方式并填入凭据。
- 配置期望的成功状态码，以及 `remote_id` 和 `remote_url` 的响应映射。
- 如果需要统一包裹请求体，编辑 Payload 模板。
