选择 GEOWorkFlow 服务器配置的关键在于明确站点规模、任务并发量以及自动化程度。单站与小型生产环境用 2 核 4 GB 即可起步；多站点或高频自动化场景则需要 8 核 16 GB 以上的独立组件部署。以下按场景梳理官方推荐配置与网络要求。

## 单站与小型生产环境的服务器配置
对于个人站点、小型团队或内部内容管理，以下配置足以稳定运行 GEOWorkFlow：
- **CPU**：2 - 4 核
- **内存**：4 - 8 GB
- **磁盘**：40 - 80 GB SSD
- **带宽**：建议 5 Mbps 以上公网带宽
- **部署方式**：使用 Nginx、Caddy 或云负载均衡做 HTTPS 反代，前端指向 GEOWorkFlow Web 服务

## 多站点与高频自动化场景的服务器配置
当需要同时管理多个站点、执行多任务并行或调用多个模型时，GEOWorkFlow 服务器配置应提升为独立服务架构：
| 组件 | 推荐配置 |
|------|----------|
| CPU | 8 核以上 |
| 内存 | 16 GB 以上 |
| 磁盘 | 200 GB 以上，建议单独挂载对象存储或独立备份盘 |
| 数据库 | 独立 PostgreSQL，开启定期备份 |

## 中大型环境下的可扩展架构
如果站点访问量大、需要支持大规模知识库与自动化信源管理，可以参照以下渐进式扩展路径：
1. 先使用单机部署，通过监控确认瓶颈
2. 将 PostgreSQL 和 Redis 迁移至独立实例
3. 拆分 Web 服务、任务队列与定时调度为独立容器或节点
4. 上传文件使用对象存储，减少本地磁盘负担
每次扩展都应在低负载窗口进行，并预先备份数据库。

## 网络端口与安全配置要求
GEOWorkFlow 依赖的出站网络必须能稳定访问 AI API 地址以及 GitHub 上的 `version.json`。入站端口管理建议如下：
- **443（HTTPS）**：生产环境必须开放，通过反向代理终止 TLS
- **80（HTTP）**：可用于证书申请或跳转 HTTPS
- **5432（PostgreSQL）、6379（Redis）**：禁止对公网开放

## 部署前检查清单与常见问题
部署或调整 GEOWorkFlow 服务器配置前，建议逐项确认以下内容：
- 服务器可访问 `https://github.com/mryeehee/GEOWorkFlow` 并能拉取 Docker 镜像
- 域名已解析，目标端口未被占用
- 若使用大陆服务器，已配置稳定的 Docker 镜像源和可访问的 AI API 服务商
- 数据库与 Redis 端口未暴露在公网
