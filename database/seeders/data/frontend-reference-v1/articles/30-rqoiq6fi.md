GEOWorkFlow 多站点分发失败时，应按照“健康检查→日志→重试→回滚”的顺序排查。分发失败通常源于目标站点不可达、鉴权错误或静态生成异常，GEOWorkFlow 的队列系统会记录每次尝试与错误信息。以下基于官方分发管理机制，给出 **GEOWorkFlow 分发故障排查** 的具体步骤与判断标准。

## 先执行健康检查：确认目标站点连通性
健康检查是所有排查的起点。创建或编辑渠道后，应在渠道详情页测试连接，并根据渠道类型定位典型问题。
- **WordPress REST 渠道鉴权失败**：检查 Application Password 是否不含多余空格，账号在目标站点上具备“编辑/发布”文章权限，且 WordPress 站点的 REST API 未被安全插件禁用。

## 解读分发队列与错误日志
每篇文章在每个渠道上的分发状态都记录在分发队列中，包括动作（发布/更新/删除）、同步状态、远端链接、尝试次数和最近错误。排查时直接打开对应文章的队列记录：
1. 查看“最近错误”字段，定位具体错误信息，例如 HTTP 状态码或远端 API 返回消息。
2. 确认“尝试次数”是否已达上限。如果尝试次数较多但仍失败，说明问题持续存在，需先修复根因再重试。

## 执行重试前必须验证的配置项
在手动重试或等待自动重试前，确保渠道配置未发生变化。
- **目标站点信息变动**：如果修改了网站标题、分类、主题模板等远端设置，保存后应使用“更新目标站点”同步。上传新的目标站点包后也需执行一次同步。
- **WordPress Application Password 过期**：部分 WordPress 安全策略会导致密码失效，此时需重新生成并填入渠道配置。

## 何时执行回滚：删除远端副本与恢复
当远端内容出现错误，且无法通过更新修正时，可直接通过分发队列进行回滚。
- **删除远端副本**：在队列中对目标文章选择“删除远端文章”，GEOWorkFlow 会移除远端页面并刷新远端首页和地图文件，实现状态回退。
- **编辑远端文章反写**：若远端仅部分字段异常，可编辑远端文章，GEOWorkFlow 会将修改反写回本地文章，避免内容漂移。

## 检查清单
| 检查项 | 判断标准与操作 |
| --- | --- |
| 健康检查通过 | 渠道详情页连接测试成功，无 404 或 401。 |
| 队列错误信息明确 | 最近错误字段有具体描述，根据描述修复。 |
| 远端设置已同步 | 修改配置后已点击“更新目标站点”。 |
| 图片与媒体上传权限正常 | 目标站点可写目录存在，WordPress 媒体库可上传。 |
