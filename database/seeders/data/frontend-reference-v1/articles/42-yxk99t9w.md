GEOWorkFlow 的结构化规则切片是系统默认推荐的知识库预处理策略。你只需在知识库创建或编辑时选择“结构化规则切片”，系统就会自动按 Markdown 标题、段落和列表等层级拆分长文档，整个过程稳定、可控，且不消耗额外的模型调用成本。以下说明其用法与适用场景。

## 什么是 GEOWorkFlow 结构化规则切片？
GEOWorkFlow 的结构化规则切片是一种完全基于原文格式的自动分块方式。它会识别 Markdown 标题层级、段落、列表、表格、引用和代码块，并在遇到超长文本时按长度继续拆分，同时保留当前章节路径和切片标题。该策略不会让任何模型改写资料内容，能够忠实地保留原始结构和信息边界，便于后续检索和溯源。

## 如何使用结构化规则切片？
操作路径集中在知识库创建和模型配置两个环节，步骤如下：
1. 在 `AI 配置器 -> AI 模型设置` 页面，将知识库切片策略设置为“结构化规则切片”；这也是系统的默认策略。
2. 创建知识库时填写名称、来源、业务线、资料时间和审核状态，然后上传原文内容。
3. 选择“保存并生成切片”，系统会自动按照规则切片，生成带元数据的知识片段。

## 结构化切片什么时候足够用？
对于章节清晰、层级分明的技术文档、操作手册或结构化报告，结构化规则切片通常已足够。只有当长文档跨章节语义联系紧密、需要更连贯的上下文划分时，才值得尝试 LLM 语义规划策略。此时系统会用聊天模型规划切片边界，但最终切片仍旧从原文重建，以保证可追溯性。

## 切片后的可靠性与回退机制
GEOWorkFlow 为切片流程设计了稳定回退：如果语义规划因模型超时、返回格式不合法或无法映射回原文而失败，系统会无条件回退到结构化规则切片，避免知识库入库中断。因此，即便你配置了 LLM 语义规划，也不会因模型异常导致切片为空或丢失。

## 常见问题
**为什么切片存在但向量是 0？**
通常因为未配置默认 embedding 模型、embedding 服务不可用，或者切片在保存时跳过了向量化步骤。配置并设为默认后，重新保存知识库即可触发向量生成。
**语义切片没生效怎么办？**
首先检查是否选择了 LLM 语义规划策略，并确认规划用聊天模型可用。
