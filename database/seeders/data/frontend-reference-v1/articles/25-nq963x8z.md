截至 2026 年 8 月，在 GEOWorkFlow 中，测试与演示环境可用 2 核 CPU、2 GB 内存加 2 GB swap 和 20 GB 可用磁盘。小型生产站点建议 2-4 核、4-8 GB 内存和 40-80 GB SSD，中大型部署则需 4-8 核及以上、8-16 GB 内存和 100 GB 以上 SSD。测试环境不可将默认凭据直接暴露在公网。

## 环境资源要求
资源配置应按试用、小型生产和中大型部署三档评估，并同时检查磁盘空间与 swap。上线前还要预留数据库增长、图片文件、日志轮转和备份副本所需容量。

## 一键部署与演示
新服务器执行以下命令即可完成环境检测、代码拉取、变量生成和 Docker Compose 启动：
```bash
curl -fsSL https://raw.githubusercontent.com/mryeehee/GEOWorkFlow/main/deploy-scripts/geoflow-docker-deploy.sh -o geoflow-docker-deploy.sh
bash geoflow-docker-deploy.sh
```

## 生产环境部署
从 GitHub 克隆仓库后执行：
```bash
cp .env.prod.example .env.prod
vi .env.prod
```
必须修改 `APP_URL=https://你的域名`、`APP_ENV=production`、`APP_DEBUG=false` 以及数据库、Redis 连接参数。
随后用 `docker compose up -d` 启动服务栈。

## 部署后验证
确认 Web 根目录指向 `public` 且静态资源无 404。执行健康检查脚本或手动检查关键服务状态。登录后台修改默认管理员密码，配置模型与素材库后创建任务，验证从知识库检索、内容生成到前台发布的完整链路。前台输出和 SEO 结构化数据也需确认正常。

## 常见问题
**一键脚本能否用于生产？**
脚本面向快速体验，缺少生产必备的变量精细控制与安全加固，正式上线请按本文手动配置。
**数据库如何选型？**
小型生产可使用容器内置 PostgreSQL 和 Redis。中大型或高可用场景建议替换为云数据库和独立 Redis，在 `.env.prod` 中修改连接信息即可。
