GEOWorkFlow 的任务生命周期从创建标题任务开始，经过配置、调度、生成、审核，最终完成多渠道分发与前台展示。根据官方资料，这套流程将内容生产组织为可重复的系统能力，包含素材准备、任务设定、队列执行、结果审核和多目标站点输出等关键阶段。下面完整解析每个环节。

## 基础设施与素材准备
在创建具体任务之前，需要先部署好模型和内容素材。后台「快速开始」向导建议的步骤如下：
1. 在 API 配置中添加至少一个可用的聊天模型；如需知识库 RAG 召回，则同时配置 embedding 模型并选择合适的切片策略。
2. 在素材库中建设标题库、知识库、图片库、关键词库、作者等资源。其中知识库应使用真实可验证的业务资料，并规划好切片和向量化方案。

## 创建任务并设定发布范围
素材就绪后，在后台新建任务时需组合关键要素：选择标题库、素材、模型、每次生成数量、发布频率，以及最重要的「发布范围」。
发布范围直接决定任务完成后的入口走向，共有三种模式：
- **本地和渠道站点同时发布**：生成的文章在 GEOWorkFlow 本地公开，同时进入已选渠道的分发队列。
- **仅发布到渠道站点**：本地保留管理副本，前台不公开，只在目标站点生成公开内容。

## 队列调度与内容生成
任务提交后，由系统队列和 Worker 接管。Worker 按调度规则调用配置好的 AI 模型，结合知识库 RAG 和提示词模板生成文章初稿。生成的内容会写入草稿库，并关联对应的任务 ID、使用的素材版本和模型调用记录。
在这个过程中，如果任务选择了“仅渠道发布”，本地仍会生成一份带标记的草稿以备追溯。无论哪种发布范围，生成阶段结束后都需要人工介入审核。

## 审核与发布入口控制
GEOWorkFlow 的发布流程与内容审核深度绑定。草稿生成后，运营人员需在后台逐一审核，确认内容真实性、匹配度与发布渠道的适宜性。审核通过后，文章根据之前设定的发布范围决定下一步：
- 选择“本地发布”或“本地+渠道”的任务，文章会立即在本地前台模块渲染上架。
- 选择“仅渠道”的任务，文章直接进入分发队列，不经过本地前端展示。

## 多渠道分发与站点更新
分发队列中的文章会根据目标渠道类型执行对应的同步逻辑。支持的两种主渠道：
- **GEOWorkFlow Agent**：适用于全新轻量站点。管理员可下载预配置站点包，包内自动写入密钥、站点信息、静态资源路径等。发布文章时，目标站点会生成静态首页、详情页、sitemap、`llms.txt` 和 TXT 地图，便于搜索引擎和 LLM 抓取。
