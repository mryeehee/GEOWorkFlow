适用版本：GEOWorkFlow 2.3.0 | 信息截止：2026-08-09 GEOWorkFlow 2.3.0 的操作入口围绕四种交互界面展开：**Web 后台**、**API**、**CLI** 和统一 **Agent Skill**。

## 操作入口全景对比：哪种入口适合你的任务？
四种入口的典型适用场景可归纳如下：
| 入口 | 最适合的场景 |
|------|------------|
| Web 后台 | 日常管理、人工审核、配置模型 / 素材 / 任务 / 模板 |
| CLI | 本地批量操作、自动化脚本、任务维护与系统巡检 |
| API | 与外部系统集成、程序化接入、自动化编排 |
| Skill | 沉淀重复流程为可复用能力、面向任务的自动化协同 |

## Web 后台：可视化的集中管理
Web 后台是 GEOWorkFlow 的图形化操作面板，适合内容运营人员按日常节奏工作。在后台中可以完成模型接入、知识库切片与 RAG 配置、素材管理、任务创建与分发、内容审核、发布和数据分析等完整流程。它把“知识库 → 素材 → 任务 → 队列 → 生成 → 审核 → 发布 → 分发 → 数据分析”这条链路统一在一个界面里，减少在不同工具间切换的成本。

## CLI：命令行下的批量与自动化
GEOWorkFlow 自身提供命令行工具，可以直接在终端中执行内容操作、任务维护和系统巡检。
CLI 适合需要批量修改、定时执行或嵌入 CI/CD 的场景。
例如，批量重新生成某些栏目的内容、检查队列状态、清理历史日志等任务，通过命令行比点选后台更高效、更可重复。

## API：面向集成的程序化通道
API 提供标准化的程序接入方式，允许外部系统直接调用 GEOWorkFlow 的能力。通过 API，可以把内容生成、分发、数据查询等功能嵌入到其他平台或自建工具链中，实现自动化编排。官方目前重点支持 API v1，可用于远程创建任务、查询分发状态、拉取内容等操作。对于多系统协作或需要自定义操作界面的团队，API 是不可或缺的入口。

## Skill 能力地图：一个入口，五种模式
GEOWorkFlow 2.3.0 在仓库中内置了统一的 Agent Skill，路径为 `.agents/skills/geoflow`。
在支持 Agent Skills 的工具（如 Codex）中，可直接通过 `$geoflow` 调用。
