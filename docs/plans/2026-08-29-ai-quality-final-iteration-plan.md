## 一、最终建议

采用“确定性预检 + 原则指标编译 + 小范围证据检索 + 单次语义裁判 + 后端验证与评分”的混合架构，继续运行在现有 Laravel、PostgreSQL、Redis、Horizon 和 Laravel AI SDK 技术栈内。

本轮 Review 保留三个核心产品原则：

1. 180 秒是一次在线质检的业务截止时间。到达截止时间必须形成明确终态，保存已完成阶段、失败阶段、可展示原因和下一步动作。
2. 技术执行结果与业务质检结论严格分开。技术失败不产生 0 分，也不产生“没有发现问题”的结论。
3. 生产门禁继续使用评分 v1。新原则层、评分 v2 和新的裁判策略先离线评测，再影子运行，达到质量门禁后分阶段接管。

本方案的质量目标、效率目标和成本目标具有相同优先级。任何 Token 或延迟优化都必须通过固定回归集和盲测集，且不能降低重大风险召回率。

## 二、本轮 Review 发现与补充

上一版方向成立，已经覆盖 3 分钟截止、错误分类、紧凑 Prompt、黄金集和灰度发布。本轮补齐以下关键设计：

| Review 发现 | 最终方案中的处理 |
| --- | --- |
| 失败态已有原因和重试入口，按钮仍缺少按故障类型分流 | 增加失败原因—动作矩阵；配额、鉴权、模型不可用直接引导配置，临时故障才提供主重试按钮 |
| 活动态可能暂存 `decision=error` | 建立状态不变量；`queued/running` 的 decision 必须为空，只有技术失败终态使用 `failed/error` |
| 缺少“质检完成”的机器可验证定义 | 明确完成条件：全部适用规则执行、全部选中主张完成验证、输出通过后端校验、评分和门禁持久化成功 |
| 失败分类没有覆盖超大输入和规则编译异常 | 新增 `input_too_large`、`principle_compilation_failed`、`principle_snapshot_unavailable` 等安全错误 |
| 多分段文章共享 180 秒，但没有正式长度边界 | 增加 5000、12000、48000 字符三级策略；超出支持范围提前给出可操作失败，不进行静默截断 |
| 知识库原则层缺少版本、来源和审核生命周期 | 增加不可变原则版本、来源追溯、适用范围、有效期、审核状态、冲突优先级和回滚契约 |
| 广告规则 hard blocker 资格缺少治理约束 | hard blocker 只来自已审核、有效且具备确定性证据或后端验证的规则版本 |
| 240 篇黄金集缺少样本分层与盲测隔离 | 固定 120 校准、60 回归、60 盲测；补齐风险分层、双人标注、第三人裁决和污染防护 |
| 指标目标缺少分母、样本量和置信区间 | 定义 SLI 分母、质量门禁、最小样本量和 95% 置信区间；任一关键维度退化即停止晋级 |
| Prompt 缓存收益依赖供应商能力 | readiness 记录缓存能力和命中用量；只对明确支持且可观测的端点启用 |
| 自动候选切换的数据授权边界需要固定 | 自动切换仅限同一已授权端点；跨供应商切换必须由管理员显式配置和确认数据范围 |
| 缺少规则更新、事故回滚和审计治理 | 增加稳定分桶、影子无门禁、版本回滚、操作审计、紧急停用开关和数据保留要求 |
| 10 倍流量下的首要瓶颈没有处理顺序 | 先暂停回填，再受控扩容前台 Worker，随后按供应商并发和日预算调节流量 |

## 三、目标、范围与非目标

### 3.1 目标

1. Provider 健康时，支持范围内文章的质检完成率达到 99.5% 以上。
2. 所有检查的终态收敛率达到 99% 以上，达到 180 秒后 5 秒内可见明确失败终态。
3. 失败态误展示 0 分或“无问题”的次数保持为 0。
4. 重大事实冲突、伪造来源和广告 hard blocker 的召回率达到 97% 以上。
5. 安全样本被 `needs_review` 或 `blocked` 的比例不超过 8%；正式评分 v2 接管前目标收紧到 5%。
6. 裁判与最终人工结论的 Cohen's Kappa 达到 0.75 以上。
7. 在质量门禁不下降的条件下，输入 Token 中位数较 legacy 下降 25% 以上，输出 Token 中位数下降 40% 以上。
8. 同一输入、同一模型和同一版本重复运行 5 次，decision 一致率达到 95% 以上。

### 3.2 实施范围

- 文章编辑页、状态 API、人工重检、发布门禁和历史记录。
- 知识一致性、数据与引文、广告合规、内容完整性四个现有维度。
- 原则指标编译、主张抽取、证据召回、语义裁判、结果校验、评分和门禁。
- 队列、截止时间、检查点、熔断、候选模型、观测、评测和灰度发布。
- 中文文章和中国大陆广告规则作为首个生产校准范围。

### 3.3 本轮非目标

- 训练或微调自有裁判模型。
- 自动改写文章正文。
- 在线抓取文章声明的任意外部 URL。
- 在首个版本覆盖多司法辖区和多语言评分。
- 引入独立微服务、向量数据库或第三方评测平台运行时。
- 用 AI 结论替代品牌、事实负责人或法律人员的最终责任。

## 四、目标架构

```text
知识库修订 / 广告规则发布
          │
          ▼
原则指标编译与人工审核 ───────────────┐
          │                           │
          ▼                           │
不可变原则快照 + 倒排索引             │
                                      │
文章快照 ──► 确定性预检 ──► 物质性主张抽取
                                      │
                                      ▼
                            适用原则选择与证据映射
                                      │
                         ┌────────────┴────────────┐
                         ▼                         ▼
                 确定性高精度判定           单次语义裁判
                         └────────────┬────────────┘
                                      ▼
                           后端引用、位置、数值校验
                                      ▼
                           确定性评分与发布门禁
                                      ▼
                 审计记录 / 状态 API / 失败动作 / 影子评测
```

选择该架构的原因：

- 确定性规则承担高精度、低成本项目，适合禁限词、必备披露、数值单位、引用存在性和结构检查。
- 原则指标层在知识或法规更新时编译，在线路径只加载当前文章适用的小集合。
- 单次语义裁判集中处理上下文、证据充分性和语义冲突，控制调用次数和 Token。
- 后端校验决定引用合法性、位置、数值冲突和 hard blocker 资格，模型不能自行发明证据或规则身份。

未采用的近似方案：

- 全量知识库、全量广告规则与正文一次性送入模型：输入规模随知识量增长，延迟、费用和上下文稀释风险持续上升。
- 纯确定性规则：对语义限定、隐含冲突和上下文例外的覆盖不足。
- 四维度多裁判并行：调用量和成本约按维度放大，首期只用于离线实验。

## 五、核心契约

### 5.1 状态与结果契约

| 执行状态 `status` | 允许的业务结论 `decision` | 分数语义 | 页面主动作 |
| --- | --- | --- | --- |
| `queued` | 空 | 未评分 | 等待 |
| `running` | 空 | 未评分 | 等待 |
| `completed` | `passed` / `needs_review` / `blocked` | 必须有总分和四维分 | 查看结果或人工处理 |
| `failed` | `error` | 必须为空 | 按错误类型处理 |
| `stale` | 空 | 历史分数只作审计，不得作为当前结论 | 按最新内容重检 |
| `cancelled` | 空 | 未评分 | 查看取消原因 |

数据库、服务、API 和页面共同遵守以下不变量：

1. 只有 `completed` 可以生成“没有发现需要标注的问题”。
2. `completed` 必须满足总分、四维分、decision、规则快照、输入指纹和完成时间均有效。
3. `failed/stale/cancelled` 的当前结果不进入发布放行计算。
4. 技术失败期间文章继续保持原发布状态；后续更新和新增分发继续受发布门禁约束。
5. 影子记录固定 `gate_applied=false`，不能成为文章当前门禁结论。
6. 文章、知识、规则、Prompt、模型或算法版本变化会使旧结果进入 `stale`。
7. 人工放行只适用于 `completed/needs_review` 且达到人工放行最低分的结果；技术失败、过期和取消结果不能人工放行。

### 5.2 “质检完成”的定义

一次检查只有同时满足以下条件才可以写入 `completed`：

- 文章处于受支持长度范围，全部分段完成。
- 本次适用的已发布原则快照已固定并可追溯。
- 所有进入预算的物质性主张具有 `supported`、`contradicted` 或 `unverified` 结果。
- 超出主张预算的高重要度主张已经形成 `needs_review` 门禁原因。
- 确定性检查、语义裁判和后端 Schema 校验均完成。
- 引用键、原文位置、数值、单位、时间和范围校验完成。
- 评分、门禁、用量、阶段耗时和审计元数据在同一终态事务中保存成功。

任何阶段缺失都进入明确失败或人工复核路径，不生成“质检完成”的成功状态。

### 5.3 失败原因与动作矩阵

| 安全错误码 | 用户可见原因 | 自动动作 | 页面主动作 | 发布处理 |
| --- | --- | --- | --- | --- |
| `provider_timeout` | 模型在分配时间内未响应 | 剩余预算足够时切换一次同端点候选 | 重试 | 保持受限 |
| `inspection_deadline_exceeded` | 排队、检索或模型阶段耗尽 180 秒 | 保存检查点并终止 | 重试 | 保持受限 |
| `provider_rate_limited` | 供应商限流 | 只接受总截止时间内的短 `Retry-After` | 稍后重试 | 保持受限 |
| `provider_gateway_error` | 网关或上游临时故障 | 剩余预算足够时切换一次候选 | 重试 | 保持受限 |
| `provider_quota_exhausted` | 账号余额或额度耗尽 | 打开熔断并暂停回填 | 补充额度 / 切换模型 | 保持受限 |
| `provider_authentication_failed` | API Key、地址或权限无效 | 标记模型不可用并暂停回填 | 检查模型配置 | 保持受限 |
| `provider_circuit_open` | 近期供应商失败率过高 | 等待半开探针 | 查看模型状态 | 保持受限 |
| `structured_output_unsupported` | 当前模型不支持目标结构化协议 | readiness 未确定且有预算时切换严格 JSON | 检查兼容性 | 保持受限 |
| `invalid_model_output` | 模型返回内容未通过 Schema 或引用校验 | 有预算时执行一次 JSON 回退 | 重试或切换模型 | 保持受限 |
| `evidence_retrieval_failed` | 知识切片或数据库检索失败 | 单次短重试 | 重试 / 检查知识库 | 保持受限 |
| `principle_compilation_failed` | 当前知识或规则未能生成有效原则快照 | 保留上一已发布版本 | 检查规则发布 | 保持受限 |
| `principle_snapshot_unavailable` | 没有可用于本次检查的已发布原则版本 | 停止模型调用 | 发布或恢复规则版本 | 保持受限 |
| `queue_dispatch_failed` | 任务未能写入队列 | 不进行模型调用 | 重试 / 检查 Redis | 保持受限 |
| `queue_worker_unavailable` | 前台质检消费者失联 | 暂停回填并告警 | 恢复 Worker | 保持受限 |
| `queue_wait_timeout` | Worker 存活但队列等待过久 | 暂停回填并记录积压 | 检查容量后重试 | 保持受限 |
| `worker_interrupted` | Worker 重启、超时或资源中断 | 截止时间内从检查点恢复一次 | 重试 / 检查 Worker | 保持受限 |
| `input_changed` | 文章或质检依据在执行中变化 | 旧检查进入 stale | 按最新内容重检 | 使用最新有效结果 |
| `input_too_large` | 正文超过单次在线质检支持范围 | 停止调用并给出字符数与上限 | 拆分文章后重检 | 保持受限 |

交互采用页面内失败卡片，保留历史原因。弹窗只用于需要确认的人工重试或切换模型操作。非重试型故障不把“立即重试”设为主按钮，防止配额和鉴权问题形成重复失败。

### 5.4 截止时间、重试和恢复

现有安全链继续保持：模型请求 160 秒、业务截止 180 秒、Job 190 秒、Worker 195 秒、队列 `retry_after` 960 秒。

执行策略固定为：

1. 所有阶段共享从检查记录创建时开始的 `deadline_at`。
2. 只有超时、限流、网关和早期无效输出允许预算内快速恢复。
3. 配额、鉴权、模型不可用、输入超限和原则快照缺失不自动重试。
4. 每次检查最多使用两个同端点候选，候选共享同一截止时间。
5. 已完成的确定性预检、主张抽取和证据映射按指纹保存检查点；恢复只重新执行未完成阶段。
6. 同一文章、同一输入指纹同时只允许一条活动记录。人工重检创建新审计记录，并复用可验证的证据缓存。
7. 对账只恢复卡住的活动记录和发布工作流补偿，不自动重试技术失败终态。
8. 熔断期间前台给出即时失败原因，回填保持暂停，半开探针只允许一个请求。

### 5.5 长文章策略

| 正文长度 | 执行方式 | 完整性约束 | 性能目标 |
| --- | --- | --- | --- |
| 不超过 5000 字符 | 单段快速路径 | 全文检查 | 成功 P50 ≤ 30 秒，P95 ≤ 60 秒 |
| 5001–12000 字符 | 单段扩展路径 | 全文检查 | 成功 P95 ≤ 120 秒 |
| 12001–48000 字符 | 最多 4 段，共享原则、证据和 180 秒截止 | 全部分段完成后才评分 | 成功 P95 ≤ 180 秒 |
| 超过 48000 字符 | 预检后进入 `input_too_large` | 不截断、不抽样放行 | 页面引导拆分文章 |

跨段聚合按根因键去重，标题、摘要、结论和全局结构在文章级单独检查。任一分段未完成，整篇保持未评分。模型输出截断时至少进入 `needs_review`，不能静默放行。

## 六、原则指标编译层

### 6.1 原则版本字段

每个不可变原则版本至少保存：

- 稳定标识、版本号、内容哈希和来源修订键。
- 来源类型：知识库、广告规则、系统规则或人工治理规则。
- 来源标题、受管来源身份、适用司法辖区和适用业务范围。
- 生效时间、失效时间、审核状态和发布状态。
- 触发条件、可验证事实字段、单位、允许范围、同义词和例外条件。
- 必须引用、建议引用、禁止表述、人工确认条件和风险等级。
- 验证方式：确定性、语义、混合或人工。
- 对应评分维度、hard blocker 资格、审核人和审核时间。

生命周期固定为 `draft → reviewed → published → retired`。在线质检只读取 `published` 且在有效期内的版本。新版本发布后通过稳定分桶和显式回填批次生效，历史检查继续引用原快照。

### 6.2 编译与选择

1. 知识库或广告规则变更后异步生成候选原则。
2. 编译器校验字段、来源、时间范围、冲突条件和 hard blocker 资格。
3. 高风险原则由授权负责人审核后发布。
4. 在线阶段先按司法辖区、业务线、产品类别、发布语境、触发词和事实字段筛选。
5. 确定性规则直接执行；语义规则与相关证据组成紧凑裁判输入。
6. 规则冲突按法律强制规则、已审核品牌事实、一般知识、写作建议的顺序处理；同层冲突进入人工复核。
7. 编译失败保留上一已发布版本并告警，新版本不能进入在线检查。

### 6.3 hard blocker 治理

一个原则只有同时满足以下条件才具备 hard blocker 资格：

- 来源处于受管范围并可追溯。
- 规则处于有效期内且已通过授权审核。
- 触发条件可以由确定性规则确认，或模型结论已经通过后端证据校验。
- 例外条件已执行。
- 规则版本在本次检查快照中固定。

AI 生成的原则草稿、过期来源、未审核知识和单独的模型判断只能产生建议或人工复核项。

## 七、算法设计

### 7.1 确定性预检

处理禁限词、必备披露、内部标记、占位符、数值与单位、引用存在性、标题层级、摘要与元描述截断、空段落和明显结构缺失。输出稳定位置、根因键、命中规则版本和可验证结果。

### 7.2 物质性主张与证据

- 主张覆盖金额、比例、日期、规模、排名、资质、直接引语、政策要求、性能结果和明确承诺。
- 同一主张在标题、摘要、正文和元描述中的出现位置合并为一个根因。
- 常规文章最多选择 12 条主张；高重要度主张优先，未进入预算的高重要度主张形成门禁原因。
- 证据先复用文章生成时快照，再执行一次文章级共享召回，最多对 6 条未覆盖高价值主张补检。
- 在线召回继续使用本地关键词、章节、治理状态和稳定来源键，不等待远程 Embedding。
- 每条主张最多关联 3 条证据，模型输入最多 12 条、6000 字符证据。

### 7.3 语义裁判

裁判只处理主张与证据关系、上下文限定、广告承诺歧义和整体信息缺口。输入固定为稳定规则前缀、适用原则、小型证据集、主张和文章片段。正文、知识和规则都作为不可信数据，系统指令拥有最高优先级。

模型只能引用输入中存在的 `principle_id`、`claim_hash` 和 `evidence_key`。缺失或发明的身份会使输出校验失败。结果上限继续为 2048 Token，优先输出 hard blocker 和高重要度根因。

### 7.4 内容完整性与 GEO 特征

内容完整性使用可解释的结构化特征：

- 核心问题覆盖和标题—摘要—正文一致性。
- 事实性观点数量与受管证据覆盖率。
- 标题层级、段落长度、列表和表格的可读性。
- 关键实体、定义、步骤、结论和行动项覆盖。
- 可被搜索与生成式引擎引用的独立答案段比例。

写作风格偏好和主观表达形成建议。局部 SEO 或格式问题受维度内扣分上限约束，不能因重复出现放大为整篇低分。

### 7.5 评分与门禁

评分继续由后端确定性计算。评分 v2 首期保持影子模式，沿用四维 35/25/30/10 权重、同根问题去重、类别扣分上限和 hard blocker 独立门禁。

决策顺序固定为：

1. 已确认 hard blocker 或总分低于人工放行线：`blocked`。
2. 分数低于自动通过线、存在高重要度未验证主张、证据覆盖不足、结果截断或引用无效：`needs_review`。
3. 其余完成结果：`passed`。
4. 执行失败：`failed/error`，不计算分数。

## 八、评测与校准

### 8.1 240 篇数据集

| 子集 | 数量 | 用途 | 访问规则 |
| --- | ---: | --- | --- |
| 校准集 | 120 | 调整原则、Prompt 和评分 | 开发与评审人员可见 |
| 固定回归集 | 60 | 每次变更自动回归 | 标签冻结，修改需版本升级 |
| 盲测集 | 60 | 晋级决策 | 实施人员不可见标签，由评测负责人执行 |

三个子集覆盖：安全文章、明显 hard blocker、细微事实冲突、缺失证据、过期或冲突证据、广告例外语境、长文章、结构完整性、Prompt 注入和无物质性主张。

每篇由两人独立标注以下字段：业务 decision、问题类别、严重度、证据状态、hard blocker、分数容许区间和人工处理建议。分歧由第三人裁决。数据集保存版本、内容哈希、标签版本、标注者角色和裁决记录。客户正文保存在私有存储；仓库只保存脱敏固定样本、Schema 和聚合报告。

### 8.2 晋级门禁

评分 v2 或新裁判版本必须同时满足：

- 重大风险召回率 ≥ 97%，95% 置信区间下界 ≥ 90%。
- 安全样本误拦截率 ≤ 5%，95% 置信区间上界 ≤ 10%。
- 问题级 Macro F1 ≥ 0.85。
- Cohen's Kappa ≥ 0.75。
- 四个维度均无超过 3 个百分点的召回退化。
- 同输入 5 次 decision 一致率 ≥ 95%。
- 支持范围内完成率、P95 延迟和 Token 目标达标。
- 盲测集每个关键风险类别至少 10 个样本；不足时补充样本后重新评测。

任何 hard blocker 类别出现新增漏检，或数据集、模型、Prompt、规则版本无法追溯，本次晋级直接停止。

### 8.3 指标口径

| 指标 | 分子 / 分母 | 统计要求 |
| --- | --- | --- |
| Provider 健康完成率 | 健康窗口内 `completed` / 支持范围内已启动检查 | 排除管理员取消和输入中途变化 |
| 全量终态收敛率 | 185 秒内进入终态 / 全部创建检查 | 每日与滚动 7 天 |

| 模型延迟 | 所有 model attempt 耗时之和 | 与端到端延迟分开 |
| 单篇 Token 成本 | 完成检查的输入、输出、推理与缓存 Token | 按模型、版本和长度分层 |
| 重大风险召回率 | 命中的人工 hard blocker / 人工 hard blocker 总数 | 报告 95% 置信区间 |
| 安全样本误拦截率 | 被 `needs_review/blocked` 的安全样本 / 安全样本总数 | 报告 95% 置信区间 |
| 稳定性 | 五次重复中多数 decision 占比 | 同输入、模型、版本、温度 |

## 九、观测、安全与治理

### 9.1 可观测性

每次检查保存排队、预检、主张抽取、原则选择、证据检索、Prompt 渲染、各模型尝试、校验、评分、持久化和总耗时。用量拆分输入、输出、推理、缓存写入和缓存读取 Token；供应商未返回的字段保持空值。

看板按模型、执行版本、评分版本、文章长度、错误码和规则版本展示：完成率、终态率、P50/P95/P99、Token、缓存命中、问题分布、人工覆盖和门禁差异。

### 9.2 告警与容量

- 前台队列等待超过 10 秒：暂停回填并告警。
- Provider 连续 5 次可重试错误，或最近 10 次失败率达到 50%：熔断 60 秒。
- 终态收敛率低于 99%：停止灰度晋级。
- 重大风险召回或安全样本误拦截越过门禁：评分 v2 比例回到 0。
- 预计流量达到当前 10 倍：先预留供应商并发和日预算，再提高前台 Worker；回填始终让位于在线检查。
- 以管理员配置的模型每日 Token 预算为分母，达到 80% 时暂停回填；达到 95% 时暂停版本重算、历史补算和非发布触发的自动重检。发布门禁与管理员明确发起的检查继续执行，并在页面展示容量预警，直到供应商硬限额生效。

### 9.3 安全、隐私和法律责任

- 状态 API 和普通日志不返回正文、证据正文、Prompt、API Key、鉴权头或供应商原始响应。
- 错误只保存安全错误码、合法 HTTP 状态、脱敏供应商代码和阶段耗时。
- 原始模型输出与分段结果继续执行 64 KiB 上限；超限保存哈希、长度和安全预览。
- 人工重试、人工放行、模型切换、规则发布、规则回滚和盲测执行写入审计记录。
- 模型配置、规则发布和跨供应商切换继续执行管理员权限校验；无权限人员只看到联系管理员的安全引导。
- 自动候选仅限同协议、主机和端口的已授权模型。跨供应商需要管理员明确配置和数据授权。
- Prompt 缓存只在 readiness 明确支持、缓存范围可控且用量可观测时启用；缓存键包含规则版本和数据授权范围。
- 广告规则必须记录司法辖区、来源、有效期和审核责任人。AI 结果提供风险辅助，最终法律判断由授权人员完成。
- 本迭代保留现有历史质检快照，不执行自动删除。原始载荷继续受 64 KiB 上限和访问控制保护；存储达到 5 GB 或月增长 20% 时触发单独的数据保留评审。
