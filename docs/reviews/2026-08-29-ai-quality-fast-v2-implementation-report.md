## 一、验收结论

本轮已完成 AI 质检效率、质量、稳定性、可观测性和渐进发布能力升级。常规文章的在线预算已经收敛到 60 秒业务截止时间，模型请求上限为 35 秒，输出上限为 2048 Token。主张、检索证据和模型输出都建立了明确上限。

“数据与引文”采用稳定证据键、语义主张和后端校验，页面短编号不再参与评分。“内容完整性”采用维度内扣分上限和同根问题合并，局部 SEO 问题不会继续放大为整篇阻断。

本轮同时补齐了专属队列、前后台隔离、熔断、模型能力档案、真实阶段耗时、安全错误码、状态 API、CLI 查询、证据缓存、生成证据复用、影子评分和黄金集评测。

当前具备进入部署环境灰度验证的条件。生产评分 v2 的切换仍需完成真实模型延迟验证和 240 篇人工标注集门禁，系统配置已默认保持 v1。

## 二、实施范围

### 2.1 性能预算

| 项目 | 升级后默认值 | 作用 |
| --- | ---: | --- |
| 业务截止时间 | 60 秒 | 可控失败在截止时间内进入终态 |
| 单次模型请求 | 35 秒 | 给校验、持久化和候选切换保留预算 |
| Job 安全超时 | 70 秒 | 覆盖业务截止后的终态写入 |
| 模型最大输出 | 2048 Token | 降低长推理和超长 JSON 风险 |
| 物质性主张 | 最多 12 条 | 控制输入规模和逐条判断量 |
| 检索次数 | 1 次文章级 + 最多 6 次补检 | 控制数据库和向量检索放大 |
| 证据 | 最多 12 条、6000 字符 | 控制 Prompt 体积 |
| 候选模型 | 最多 2 个 | 在截止时间内完成快速切换 |
| 原始输出留存 | 每层最多 64 KiB | 控制数据库膨胀和异常载荷风险 |

业务截止时间从质检记录创建时开始，排队和分段间隔都会消耗同一份 60 秒预算。阶段耗时使用单调时钟记录。候选模型只有在剩余时间足够时才会启动。结构化输出能力已知不可用时直接使用严格 JSON；默认每 24 小时允许一次结构化能力复探。

### 2.2 主张抽取与证据检索

`ArticleFactCandidateExtractor` 现在会：

- 在抽取前清理内部临时引用标记。
- 过滤列表序号、产品型号、普通问句和低物质性数字。
- 对标题、摘要、正文和元描述进行跨字段归一化去重。
- 保留同一主张的出现次数和位置，同时只形成一个根主张。
- 按物质性排序并限制为 12 条。

`ArticleAiQualityEvidenceBuilder` 现在会：

- 优先复用生成时证据；没有可复用快照时执行一次文章级共享候选检索。
- 在线质检检索使用本地关键词、章节和治理排序，避免远程 Embedding 请求占用 60 秒预算。
- 将共享候选与物质性主张做保守语义匹配，只为尚未覆盖的主张补检。
- 只为未覆盖的高价值主张执行最多 6 次补检。
- 使用 `knowledge_base_id + chunk_id + content_hash` 形成稳定证据键。
- 按 12 条和 6000 字符双重预算截断。
- 优先复用文章生成时真实使用的证据快照。
- 复核知识库、切片、内容哈希、来源哈希和治理状态后才接受生成证据。

精确证据缓存覆盖文章内容哈希、知识版本、主张哈希、生成证据哈希、检索版本和预算。缓存加锁防止并发击穿，解析器异常只执行一次并向上抛出。

### 2.3 评分和误判治理

评分 v2 已实现以下规则：

- 页面 `K1`、`K2` 等短编号只用于展示。
- 同一根主张或同一引用根因只扣一次分，同时保留全部出现位置。
- 数据与引文问题的单类扣分上限为 4 分。
- SEO 与普通完整性问题的单类扣分上限为 3 分。
- 同一知识主张的累计扣分上限为 10 分。
- 证据不足形成 `unverified` 和人工确认项，不直接扣质量分。
- 已确认的重大事实冲突、伪造来源和法律红线继续触发 hard blocker。
- 置信度、证据覆盖和门禁原因与质量分分别持久化。

模型输出先经过严格 Schema 校验，再由后端核对字段、原文位置、证据键和冲突条件。未获得稳定证据支持的 critical 数据冲突会被降为待确认项，避免裁判模型单独形成重大阻断。

### 2.4 队列和异常恢复

新增两个隔离队列：

| 队列 | 默认并发 | 任务 |
| --- | ---: | --- |
| `ai-quality` | 2 | 新文章、人工重检、发布门禁 |
| `ai-quality-backfill` | 1 | 对账、异常恢复、版本回填 |

回填每批最多处理 25 篇，并记录游标。出现以下条件时暂停回填：

- 前台质检等待超过 10 秒。
- 质量模型熔断中。
- 模型当日额度接近保留水位。

定时对账调整为每分钟执行。排队或运行状态超过 60 秒的记录会进入恢复流程。算法版本变化不会自动触发无界重检，版本升级通过稳定分桶、影子评测和显式比例控制。

生产 Compose 默认启动 2 个在线质检副本和 1 个回填副本。健康检查会核对两个服务都在运行，并确认在线副本数达到 `AI_QUALITY_QUEUE_REPLICAS`。源码部署、预构建镜像和本地开发脚本使用同一组可配置队列名。

### 2.5 供应商稳定性

运行异常已经形成类型化错误：

- 鉴权失败。
- 限流。
- 配额耗尽。
- 请求超时。
- 网关或上游错误。
- 结构化输出不支持。
- 模型输出无效。
- 证据检索失败。
- 业务截止时间到达。

出站层保留 HTTP 状态、供应商错误码和安全原因类型。异常链只包含脱敏原因，不保存 API Key、请求地址、原始响应体或底层连接错误文本。

熔断默认在连续 5 次可重试失败，或最近 10 次调用失败率达到 50% 时打开 60 秒。半开状态只放行一个探测请求。供应商鉴权、超时和网关错误会进入候选模型切换；候选模型必须与主模型使用相同协议、主机和端口，文章与证据不会被发送到未授权的其他端点。结构化能力错误才会触发严格 JSON 回退。

### 2.6 模型能力档案

`article_quality_structured_output` readiness profile 记录：

- 模型配置指纹。
- 最近 20 次结构化 Schema 通过率和错误率。
- 延迟 P50、P95。
- 最近成功时间。
- 结构化和 JSON 模式状态。

供应商超时不会被误记为 Schema 不兼容。配置变化会使旧档案失效，结构化模式降级后按复探周期重新验证。

### 2.7 进度、状态和排障

后台进度增加：

- 当前阶段。
- 已用时间。
- 60 秒截止时间。
- 抽取、检索、提示、模型、校验、评分、持久化和总耗时。
- 安全错误码与是否可重试。

终态耗时以 `finished_at` 为准，不会在页面刷新后持续增长。55 秒后页面提示正在结束本次检查。

## 三、版本与灰度策略

版本策略以文章 ID 稳定分桶，支持三组独立比例：

- `GEOFLOW_AI_QUALITY_FAST_V2_PERCENT`：v2 紧凑 Prompt、稳定证据键和结构化结果契约。
- `GEOFLOW_AI_QUALITY_SHADOW_V2_PERCENT`：v2 影子评分。
- `GEOFLOW_AI_QUALITY_SCORING_V2_PERCENT`：v2 正式门禁。

影子记录通过 `baseline_check_id` 关联主记录，设置 `gate_applied=false`，不会成为文章最新门禁结论。影子记录只保存评分结果和必要元数据，不复制文章、Prompt、证据、原始模型输出与用量载荷。

60 秒截止时间、专属队列、证据预算、异常分类和熔断属于安全基础设施，对 legacy 和 fast_v2 均生效。执行比例控制 Prompt 与结果 Schema 的版本切换；legacy 使用配套 v1 Prompt 和 v1 结构化 Agent，fast_v2 使用 v2 根因契约。两种路径使用同一套指纹计算，发布门禁、执行服务和恢复任务不会出现版本漂移。

推荐灰度顺序：

1. 保持三个比例均为 0，完成部署和队列健康检查。
2. 快速链路提高到 10%，影子评分提高到 10%，正式门禁保持 0。
3. 观察至少一个完整发布周期，核对 P50、P95、失败率和误判差异。
4. 黄金集满足生产门禁后，将快速链路和影子评分逐级提高到 50%、100%。
5. 正式评分按 10%、25%、50%、100% 逐级提高，每一级保留回滚观察窗口。

配置回滚可以立即恢复 legacy 执行和 v1 评分，无需删除历史审计记录。

## 四、黄金集与生产门禁

新增离线与真实模型共用的评测命令：

```bash
php artisan geoflow:evaluate-ai-quality
php artisan geoflow:evaluate-ai-quality --live --model=MODEL_ID
```

报告包含：

- decision 混淆矩阵。
- 安全样本误拦截率。
- 重大风险召回率。
- 问题级 Macro F1。
- Cohen Kappa。
- 模型延迟、输入 Token 与输出 Token 的 P50、P95。

当前 starter 数据集包含 6 个合成与脱敏样本，只用于验证评测框架。离线保存结果与标签一致：安全样本误拦截率 0%，重大风险召回率 100%，Macro F1 1.0，Kappa 1.0，延迟样本 P95 21 秒。该结果来自夹具中的离线预测与历史样本值，不能代表真实模型生产性能。

生产门禁要求：

- 240 篇双人独立标注样本，其中校准 120、固定回归 60、盲测 60。
- 分歧由第三人裁决。
- 安全样本误拦截率不超过 3%。
- 重大风险召回率不低于 95%。
- 问题级 Macro F1 不低于 0.85。
- Cohen Kappa 不低于 0.75。
- 常规文章真实端到端 P95 不超过 55 秒。

当前命令的评测范围为模型级。端到端延迟和同输入重复稳定性尚无真实样本时，对应门禁固定为未通过。样本数量、质量指标、端到端延迟与重复稳定性全部满足后，`production_gate_ready` 才能变为 `true`。

## 五、实施 Review 结果

### 5.1 已发现并修复的问题

| Review 发现 | 处理结果 |
| --- | --- |
| 缓存锁超时处理可能让解析器异常再次执行 | 仅捕获锁超时，解析器异常直接上抛 |
| 终态页面已用时间会随刷新持续增长 | 终态固定使用 `finished_at` |
| 结构化降级状态可能永久不再探测 | 增加 24 小时复探和配置指纹失效 |
| 鉴权、超时或网关异常可能误触发同模型 JSON 重试 | JSON 回退仅用于结构化能力错误 |
| 回填压力检查只看前 50 条记录，可能漏掉真正的前台检查 | 查询改为按触发类型直接判断是否存在超时前台任务 |
| 原始底层异常作为 previous exception 可能进入日志 | 新增脱敏原因异常，只保留安全类型和状态元数据 |
| 影子记录复制原始输出和全部快照 | 影子记录改为轻量评分审计 |
| 提示词 v2 回滚只改版本号，内容仍保持 v2 | 增加兼容 v1 资源，升级和回滚同步切换内容与版本 |
| 质量 readiness 使用历史任意成功样本，最新能力失败仍可能显示 ready | 改为以最新结构化样本判定，供应商故障保留已有能力状态 |
| 质量探测可能覆盖 AI 工作台的全局结构化状态 | 质量能力只更新独立 profile，不再修改全局字段 |
| 定向对账任务会清空或覆盖全量回填游标 | 只有无上限全量回填任务可以维护全局游标 |
| 质量异常链可能保留数据库或 SDK 原始错误 | 统一替换为安全原因类型，原始消息不进入失败任务 |
| 物质性候选按字段顺序截断，后出现的高风险主张可能丢失 | 截断前按物质性和稳定位置排序 |
| unverified 在校验后移出 issues，评分器无法形成预期人工门禁 | 不扣分的同时写入专用门禁原因 |
| SEO 类别上限只存在于评分器测试，校验结果缺少类别 | 后端按摘要与元描述字段派生 `seo_truncation` |
| 执行版本只改变指纹，Prompt 和 Schema 没有真实切换 | 增加 legacy/v2 Prompt 快照和双结构化 Agent，统一门禁指纹入口 |
| 首条证据可能突破总字符预算，并发缓存锁的租期短于模型前置处理窗口 | 首条证据也按剩余字符截断，缓存锁租期覆盖完整证据构建窗口 |
| 共享候选命中后仍会逐条补检，生成证据复用也没有减少检索调用 | 对共享证据进行保守主张映射，已覆盖主张不再重复检索，生成证据可直接替代共享检索 |
| 在线检索可能连续等待远程 Embedding 请求，挤占模型判断时间 | 质检链路使用确定性本地混合召回，远程 Embedding 保留给知识同步和文章生成链路 |
| 没有物质性事实主张的文章会因零证据被强制人工复核 | 无物质性主张时证据覆盖判定为充分，广告与内容问题继续独立检查 |
| 已失败记录由定时对账自动重试时，供应商持续故障可能形成无限检查链 | 失败记录保持终态，`retryable` 仅指导人工重检；对账只恢复卡住的排队或运行记录 |
| 预构建镜像部署没有独立质检消费者 | 为 prebuilt Compose 补齐前台和回填两个质检 Worker |
| 提示词升级假设系统提示词记录始终存在 | v2 迁移在记录缺失时按版本化资源安全重建 |
| 多分段文章在当前 Job 释放互斥锁前投递同键后续 Job，双 Worker 下可能消耗唯一尝试 | 后续分段使用短延迟投递，确保当前执行完成并释放互斥锁后再领取 |
| 离线预测也可能满足生产门禁，安全样本进入人工复核没有计入误拦截 | 生产门禁要求真实模型模式和 P95 延迟达标，`needs_review` 与 `blocked` 均计入安全样本误拦截 |
| JSON 中的文章正文可闭合提示词边界标签并注入新指令 | JSON 序列化启用标签字符转义，正文中的 `<` 与 `>` 不再形成提示词控制结构 |
| 智能故障切换会把正文和证据发送给任意启用的聊天模型 | 候选模型限制为与主模型相同的端点来源，阻止跨供应商隐式传输 |
| 生产部署脚本没有启动质检消费者，页面会长期停在“质检中” | 三套 Compose、部署脚本、健康检查和多语言部署命令均加入在线与回填质检服务 |
| 在线质检只有一个副本，`container_name` 阻止横向扩容 | 移除在线服务固定容器名，默认启动两个副本，健康检查核对实际副本数 |
| 本地开发脚本把普通长任务和 75 秒质检 Worker 混在一起 | 普通队列恢复 930 秒 Worker，在线质检和回填各用独立 75 秒消费者 |
| 部署停机命令仍引用已移除的 `system-update-queue` 服务 | 旧容器通过 Docker 直接停止，Compose 停机列表只保留当前存在的服务，避免部署在迁移前中断 |
| 分段任务的进程互斥会在竞争时消耗唯一尝试 | 移除进程互斥中间件，保留数据库原子领取与唯一投递约束 |
| 60 秒预算在 Worker 启动和每个分段重新计时 | 截止时间固定从质检记录创建时计算，排队和所有分段共用同一预算 |
| 质检完成后发布状态或分发入队失败没有补偿记录 | `workflow_apply` 持久化处理状态，对账任务最多补偿 3 次，连续失败后进入 `exhausted` 并保留人工处理状态 |
| Prompt 中的版本提示文字被用来推断结果 Schema | 执行服务通过版本化 Reviewer 接口显式传入 `legacy` 或 `fast_v2` |
| 模型级离线报告可以绕过端到端延迟和重复稳定性门禁 | 报告写明 `evaluation_scope=model_only`，缺失门禁保持 `false`，输入与输出 Token 分开统计 |
| 评测报告写入开发机绝对路径 | 仓库内数据集统一记录相对路径，避免泄露本机目录并提高报告可移植性 |
| API 的 `failed` 筛选混入待复核和业务阻断结果 | `failed` 只表示技术失败，新增 `needs_review` 与 `blocked` 业务筛选，保留 `error` 兼容别名 |
| 批量失效一次性加载全部质检 ID | 按 500 条分块更新质检与分段记录，并只保留受影响文章范围 |
| 补充检索返回的任意证据会覆盖当前事实主张 | 补充证据继续经过保守语义映射，无关证据保持未覆盖 |
| “产品价格说明”“客户增长率分析”“行业认证介绍”等标题被误抽成事实主张 | 金额、百分比和资质规则要求出现数值或明确断言，描述性标题不会触发严格证据门禁 |

### 5.2 安全 Review

- 状态 API 只返回轻量结果，不返回正文、证据正文、Prompt 或供应商原始异常。
- Prompt 数据段使用标签字符转义，文章正文不能提前结束数据边界。
- 出站失败记录已脱敏，测试覆盖 Token、URL 和 TLS 原因文本不泄露。
- 证据复用必须通过知识库范围、切片身份、内容哈希、来源哈希与治理状态校验。
- 智能故障切换只在同一端点来源内选择候选模型。
- 模型原始输出、分段结果和异常预览均有存储边界。
- 影子记录不会参与发布门禁或最新结果关系。

### 5.3 架构 Review

- 保持 Laravel 单体、Redis、Horizon 和现有 AI SDK，没有新增运行时平台依赖。
- 快速执行、评分 v2 和影子评测使用独立开关，可分别回滚。
- 前台与回填队列隔离，避免批量任务抢占人工操作。
- 在线 Worker 默认双副本，部署健康检查同时验证服务和容量。
- 评分器、校验器、证据构建器、版本策略、熔断和 readiness 保持独立职责。
- 对账任务保留游标和压力暂停条件，支持渐进回填。
- 质检结果与后续发布工作流分别持久化，后续工作流失败最多补偿 3 次。
