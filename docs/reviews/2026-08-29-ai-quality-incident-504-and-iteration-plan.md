# AI 质检 #504 故障复盘与迭代方案

## 结论

文章 #504 的最近一次质检没有形成有效评分。模型调用持续约 35 秒后触发原请求上限，记录以 `failed/error` 结束，`score`、四个维度和问题列表均为空。页面把空维度转换成 0，又把空问题列表解释成“没有发现需要标注的问题”，于是同时出现质检异常、0 分和绿色无问题提示。

本轮已经修复失败态表达，放宽端到端预算，并启用紧凑执行链路。系统现在允许单模型最多执行 160 秒，整次检查最长 180 秒，预留 10 秒完成校验与持久化；Job 和 Worker 分别在 190 秒、195 秒形成安全边界。失败记录展示具体安全原因、尝试耗时、可执行的下一步和人工重试入口，空评分继续保持“未评分”语义。

上线后的真实回归发现当前 DeepSeek 账户返回 HTTP 402 `Insufficient Balance`。新的异常链将其记录为 `provider_quota_exhausted`，页面引导管理员补充余额、配额或切换备用模型。当前外部阻塞已经精确定位，补足模型余额后即可继续验证完整评分结果。

## 一、事故证据

| 证据 | 观察结果 | 判断 |
| --- | --- | --- |
| 最新质检记录 | `status=failed`、`decision=error` | 本次执行没有完成 |
| 评分字段 | 总分、维度、问题均为空 | 没有可用于评分的模型结果 |
| 异常码 | `provider_gateway_error` | 历史记录只保留了脱敏后的通用连接异常 |
| 三次历史尝试 | 每次约 35.2 秒、Token 用量为 0 | 与原 35 秒请求上限高度吻合 |
| 同文旧记录 | 曾在更长运行时间内得到 90 分 | 文章内容本身不会稳定触发 0 分 |
| 当前供应商探针 | HTTP 402、`Insufficient Balance` | 当前模型账户余额不足，无法生成新的评分 |

历史异常在出站层完成脱敏后丢失了 cURL 原始分类，因此无法从旧记录精确区分连接超时、DNS、TLS 与 502/504。新的实现会在脱敏前提取安全传输类别，后续记录可以稳定区分 `provider_timeout`、`dns`、`tls`、`connection` 和 `gateway`。

## 二、已经落地的修复

### 2.1 状态与页面语义

- `completed` 才进入评分、维度和问题展示。
- `failed`、`stale`、`cancelled` 与 `decision=error` 进入独立失败卡片。
- 失败卡片展示安全错误码、具体原因、模型尝试时长、HTTP 状态或脱敏供应商代码、下一步建议。
- 可重试故障提供“按已保存内容重试”，复用专用重检路由，避免误提交文章表单。
- 缺失分数显示“未评分”，缺失维度显示破折号，失败态不会显示绿色“没有发现问题”。
- 状态 API 增加结构化 `failure` 对象，前端和其他客户端可以使用同一份原因映射。
- HTTP 异常会在脱敏前提取状态、供应商错误码和安全类别；当前 402 已准确归类为余额或配额耗尽。

### 2.2 执行预算

```text
模型请求上限 160 秒
  < 业务截止 180 秒
  < Job 超时 190 秒
  < Worker 超时 195 秒
  < 队列 retry_after 960 秒
```

固定单模型可以使用完整请求预算。配置多个同端点候选时，首个候选使用约 65% 的可用请求预算，为一次候选切换留下约 60 秒。所有候选共享同一个 180 秒截止时间，防止串行重试无限延长。

### 2.3 紧凑执行与 Token 控制

- 默认执行版本切换为 `fast_v2`，评分门禁继续使用已上线的 v1 评分，评分 v2 保持影子开关。
- 模型输入只投影裁判需要的主张、证据和法规字段；数据库仍保存完整审计快照。
- 文章 #504 的渲染输入从 23,966 字符降到 18,048 字符，降幅约 24.7%。
- 输出继续限制为 2,048 Token，并使用紧凑根因 Schema，减少模型生成长解释与重复问题。
- 证据缓存键包含文章、知识版本、主张哈希、生成证据、检索版本和预算，重复重检可以复用稳定证据。

字符降幅只能说明 Prompt 体积下降。真实 Token、延迟与费用需要通过生产同模型 A/B 样本验证后形成结论。

## 三、当前架构盘点

```text
文章快照
  -> 确定性清理与物质性主张抽取（最多 12 条）
  -> 生成证据复用 / 本地共享召回 / 未覆盖主张补检
  -> 广告规则快照与适用范围
  -> 一次紧凑语义裁判
  -> 后端 Schema、引用、位置、数值和冲突校验
  -> 确定性评分与发布门禁
  -> 审计记录、状态 API、失败引导
```

已经具备的基础能力包括专属前台与回填队列、熔断、候选模型、证据缓存、稳定来源键、失败终态收敛、阶段耗时、用量元数据、影子评分和离线黄金集框架。

仍需加强的部分：

1. 当前黄金集只有框架样本，尚未达到生产校准规模。
2. 知识库与广告规则仍以检索快照为主，缺少正式的“原则指标编译层”。
3. `fast_v2` 的真实模型成功率、Token 与延迟没有完成同模型 A/B。
4. 评分 v2 尚未经过双人标注、第三人裁决与盲测门禁。
5. 供应商侧 Prompt 缓存能力需要按具体协议确认，当前不能假设 DeepSeek 兼容端点提供可观测缓存命中。

## 四、领先实践与可借鉴设计

### 4.1 用人工标签校准模型裁判

OpenAI Evals 将高质量评分规则与人工 choice labels 作为模型裁判元评测的核心输入。GEOWorkFlow 应把“人工放行结论、问题类别、严重度、证据充分性”形成版本化私有数据集，使用裁判与人工一致率决定版本晋级。[OpenAI Evals](https://github.com/openai/evals) · [Build an eval](https://github.com/openai/evals/blob/main/docs/build-eval.md)

### 4.2 将事实忠实度拆成主张与证据支持

Ragas 的 faithfulness 流程先把回答拆成可验证主张，再逐条判断上下文支持度。这与现有物质性主张抽取方向一致，下一步应把每条主张的 `supported / contradicted / unverified` 保存为稳定中间结果，并让评分只消费已校验状态。[Ragas Faithfulness](https://github.com/vibrantlabsai/ragas/blob/main/docs/concepts/metrics/available_metrics/faithfulness.md)

### 4.3 确定性断言与模型断言组合

DeepEval 和 Promptfoo 都支持组件级与端到端评测、确定性断言、模型评分、权重和关键指标阈值。GEOWorkFlow 可用确定性规则处理广告禁词、数字格式、引用存在性和 Schema；模型集中处理语义冲突、证据充分性与主观完整性。[DeepEval](https://github.com/confident-ai/deepeval) · [Promptfoo assertions](https://www.promptfoo.dev/docs/configuration/expected-outputs/) · [Promptfoo CLI](https://www.promptfoo.dev/docs/usage/command-line/)

### 4.4 规则索引与预计算

OPA 的性能指南强调索引、对象查找和 partial evaluation。知识库与广告法可以在发布时编译为小型原则索引：适用主体、产品类别、地域、时间、触发词、事实字段、风险等级和验证方式。在线阶段先确定适用规则集合，再把少量候选送入模型。[OPA Policy Performance](https://www.openpolicyagent.org/docs/policy-performance)

### 4.5 稳定前缀缓存

Anthropic 的 Prompt Caching 文档建议把稳定内容放在前缀并设置明确缓存断点。供应商支持缓存时，系统提示、评分规则和法规原则索引适合稳定前缀；文章、动态证据和主张放在后部。需要在 readiness profile 记录缓存命中、写入 Token 与读取 Token，再判断成本收益。[Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 五、目标算法与工程架构

### 5.1 原则指标编译层

知识库入库或更新时异步生成 `quality_principles`：

- `principle_id`、版本、适用范围、有效期、来源稳定键。
- 可验证事实字段、单位、允许范围、同义词、冲突条件。
- 必须引用、建议引用、禁止表述、人工确认条件。
- 风险等级、对应评分维度与 hard blocker 资格。

广告规则按司法辖区、产品类别、媒介、触发词和例外条件编译。在线检查通过结构化字段和倒排索引获得候选规则，模型只接收与文章相关的小集合。

### 5.2 两级检查

第一级使用确定性引擎处理高精度项目：禁限词、必备披露、数字与单位、引用存在性、标题与正文结构、段落和 GEO 可读性特征。第二级语义裁判处理主张与证据关系、上下文限定、容易产生歧义的广告承诺和整体信息缺口。

“内容完整性”采用结构化特征评分：核心问题覆盖、事实性观点数量、可引用证据覆盖、标题层级、摘要一致性、结论与行动项。主观写作偏好只形成建议，不触发低分或发布阻断。

### 5.3 可恢复执行

- 主张抽取、证据构建、模型裁判和后端校验使用幂等指纹。
- 完成的确定性阶段和证据阶段写入可复用检查点。
- 重试只重新执行失败阶段，文章或规则版本变化时使相关检查点失效。
- 外部失败记录端点、候选、阶段、耗时、安全类别、HTTP 状态、供应商代码和重试建议。
- 供应商健康时优先完成当前调用；达到 180 秒后形成明确失败终态并保留所有已完成阶段证据。

## 六、迭代路线与门禁

| 阶段 | 时间建议 | 交付 | 晋级门禁 |
| --- | --- | --- | --- |
| P0 故障修复 | 已完成 | 3 分钟预算、真实失败态、重试入口、安全分类、Prompt 投影 | 自动化回归通过；失败态零误报“无问题” |
| P1 数据与规则编译 | 1–2 周 | 240 篇双人标注集、知识原则 Schema、广告规则编译器、稳定来源治理 | 标签争议完成第三人裁决；关键类别覆盖完整 |
| P2 影子与 A/B | 1–2 个发布周期 | `fast_v2` 与 legacy 同文对比、评分 v2 影子、缓存与供应商指标 | 重大风险召回率和人工一致率达标；成本与延迟有实测优势 |
| P3 灰度发布 | 1 个发布周期 | 10%→25%→50%→100% 稳定分桶、自动回退 | 每档至少观察一个业务周期且无阻断回归 |
| P4 持续校准 | 持续 | 误报/漏报样本回流、规则版本治理、月度裁判校准 | 指标漂移触发暂停晋级或回退 |

建议生产指标：

- Provider 健康样本完成率 ≥ 99.5%，全量终态收敛率 ≥ 99%。
- 失败态“无问题”误展示为 0。
- 常规文章成功 P95 目标 ≤ 180 秒，同时持续观察 P50/P95，避免把上限当成性能目标。
- hard blocker 召回率 ≥ 97%，安全样本误拦截率 ≤ 8%。
- 裁判与人工决策 Cohen's Kappa ≥ 0.75。
- 同输入重复 5 次的 decision 一致率 ≥ 95%。
- 在质量门禁不下降的条件下，输入 Token 中位数下降 ≥ 25%，输出 Token 中位数下降 ≥ 40%。

- AI 质检与安全出站相关 263 个自动化测试通过，共 1,305 条断言；前端进度组件 6 个测试通过。
- 覆盖失败态 API 与页面、重试按钮、空评分语义、超时链、候选预算、传输分类、HTTP 402 余额分类、Prompt 投影、历史记录和健康检查。
- 前端生产构建和 Blade 编译通过，队列健康检查确认 2 个在线 Worker、1 个回填 Worker 与 180/190/195/960 秒超时链正常。
- 文章 #504 已于 10:47 被移入回收站，本轮没有恢复或修改该文章。使用同类历史失败文章 #494 执行真实回归，检查 #17 在约 2 秒内准确收敛为 `provider_quota_exhausted`，同时保存 HTTP 402 和 `invalid_request_error`。
- 模型余额恢复后应再次执行真实评分，记录成功耗时、输入与输出 Token、维度评分和问题召回。算法晋级仍以完整人工标注集为准。
