# GEOWorkFlow 新旧系统融合最终实施方案

> 状态：Final v2.0，待用户确认后实施
>
> 日期：2026-08-23
>
> 最终代码库：`GEOWorkFlow`
>
> 最终管理后台：`http://localhost:18080/admin`
>
> 数据基准：当前 `GEOWorkFlow` 数据库、站点设置、前台模板与文件
>
> 界面基准：`GEOWorkFlow-UI-V3` 的真实管理页面与 AI 工作台

## 1. 最终结论

本次融合采用“保留 GEOWorkFlow 业务与数据，迁入 UI V3 和 AI 工作台”的路线。

完成后只保留以下一套系统：

- 一个代码目录和代码库：`GEOWorkFlow`。
- 一个管理后台入口：`http://localhost:18080/admin`。
- 一套 PostgreSQL 数据：沿用当前 18080 系统的数据。
- 一套 Redis、队列、调度和实时事件服务。
- 一套前台模板与站点设置：沿用当前 18080 系统的主题、首页模块、内容和测试数据。
- 一套管理界面：采用 UI V3 公共壳层和页面样式。
- 一个真实 AI 工作台：保留 UI V3 交互，接入受控 Agent、审批、队列、审计和恢复链路。

`http://localhost:28080` 只用于融合期间的候选版本验收。完成切换和观察后，删除 UI V3 的独立容器、网络、数据库卷和源码目录。

## 2. 本轮 Review 结论

原方案的主方向正确，已经覆盖界面迁移、旧数据保留、AI 工作台接入和最终单系统收口。本轮补齐了会直接影响实施安全与验收结果的十二项内容：

1. 增加双工作树保护，先固化两边未提交内容，再进入干净集成工作树。
2. 明确 UI V3 分支是当前 GEOWorkFlow 基线的直接后续提交，可以保留连续 Git 历史，减少人工拷贝。
3. 增加旧数据库逻辑备份与克隆验证，禁止复制正在运行的 PostgreSQL 数据目录。
4. 增加 `APP_KEY`、加密模型密钥、Session、站点域名和文件存储的保留规则。
5. 增加最终容器拓扑，补齐 Nginx 静态资源网关、两条 AI 队列、Scheduler 和 Reverb。
6. 增加资源缓存规则，Vite 指纹资源长期缓存，动态页面禁用缓存，主题与上传资源采用短缓存。
7. 增加数据库变更清单、迁移验证和前向修复原则，避免错误回滚共享会话表。
8. 增加 AI 模型结构化输出检测、运行时灰度、外部操作沙箱和 `outcome_unknown` 对账门禁。
9. 增加切换前的队列排空、调度暂停、维护窗口和服务恢复顺序。
10. 增加输入框、首页文案模块、处理中状态和居中错误弹窗的明确验收标准。
11. 增加全后台路由、权限、表格、表单、主题、上传、国际化和异常页的回归矩阵。
12. 增加 48 小时观察期、两级回退和最终清理条件，确保只保留一套系统时仍有可恢复版本。

评审结论：方案可以进入实施，前提是先完成第 7 节的阶段 0。当前两个目录都有大量未提交内容，直接合并会造成用户工作丢失风险。

## 4. 融合原则

### 4.1 数据原则

- 旧系统数据库、`APP_KEY`、文件存储、站点设置和前台主题保持原位。
- UI V3 演示数据库只用于对照，不做整库合并，不导入演示 Seeder。
- 数据迁移只增加 AI 工作台所需结构，不覆盖现有业务表内容。
- 所有备份先完成恢复演练，再进入正式迁移。
- 数据校验采用表数量、关键行数、时间范围、配置摘要和文件清单共同判断。

### 4.2 业务原则

- 原有控制器、领域服务、权限、验证、队列和发布流程继续作为业务事实来源。
- UI V3 迁移页面结构、样式、公共组件和交互方式。
- AI 工作台通过能力注册表和领域服务执行操作，模型不直接调用任意路由、SQL、Shell 或文件系统。
- 外部写入必须经过计划、审批、幂等、目标复核和结果对账。
- AI 创建的内容、任务和知识先进入草稿或暂停状态，继续使用原业务审核流程。

### 4.3 发布原则

- UI V3 和 AI Runtime 使用两个独立开关，初次发布时 AI Runtime 保持关闭。
- 候选环境通过后再切换 18080。
- 观察期内保留旧 UI 回退能力，数据始终使用同一套旧系统数据。
- 观察期结束后发布收口版本，删除旧壳层、临时开关和 28080 隔离环境。

测试代码可以保留专用 Seeder，但必须只在测试环境显式调用，正式启动和部署流程不得引用。

### 5.3 本次不扩展的范围

- 不修改公开 API 契约。
- 不更换数据库、Redis、Laravel、Laravel AI 或前端框架。

## 6. 最终技术架构

```text
浏览器
  |
  v
geoflow-web :18080
  |-- /build/assets/*  指纹资源，长期缓存
  |-- /reverb/*        同源实时事件
  |-- 主题与上传资源    短缓存
  `-- 动态请求          no-store
          |
          v
      geoflow-app
          |
          |-- PostgreSQL，沿用旧数据目录
          |-- Redis，缓存、锁、队列、Session
          |-- geoflow-queue
          |     |-- ai-workspace-interactive
          |     |-- ai-workspace
          |     |-- geoflow
          |     |-- distribution
          |     |-- theme-replication
          |     `-- default
          |-- geoflow-knowledge-queue
          |-- geoflow-system-update-queue
          |-- geoflow-scheduler
          `-- geoflow-reverb :18081
```

### 6.1 本地与生产拓扑

本地最终入口也使用 Nginx 网关。应用容器只提供内部服务，18080 由 `geoflow-web` 暴露。这样可以统一静态资源缓存、动态页面缓存和 Reverb 同源行为，并保留 UI V3 已验证的首屏防闪烁策略。

生产继续使用现有 `web + php-fpm` 结构，并同步以下缓存规则：

- `/build/assets/`：`Cache-Control: public, max-age=31536000, immutable`。
- 动态 HTML 和后台页面：`Cache-Control: no-store`。
- 非指纹主题、图片和上传资源：短缓存，不设置 `immutable`。
- 隐藏文件与可执行 PHP 路径：直接拒绝。

### 6.2 队列与超时

- `ai-workspace-interactive` 处理意图解析、追问、普通回答和计划生成。
- `ai-workspace` 处理审批后的领域工作流。
- AI 执行任务最长 900 秒，Worker 超时 930 秒，Redis `retry_after` 不低于 960 秒。
- 两条 AI 队列必须有独立等待时间指标和失败记录。
- `geoflow:recover-ai-workspace` 每 5 分钟运行。
- `geoflow:prune-ai-workspace` 每天 02:30 运行。
- 调度任务使用单机锁和防重叠约束。

默认 Compose 继续使用独立 `queue:work` 容器。`config/horizon.php` 同步维护两条 AI 队列的 Supervisor 配置，供启用 Horizon 的部署使用。两种消费模式只能启用一种，避免重复消费者和重复监控结论。

Reverb 作为实时体验增强。连接失败、事件丢失或序号不连续时，页面自动读取 Run 权威快照，不能依赖前端动画推断任务完成。

## 7. 实施阶段

每个阶段都有独立交付物和门禁。任一门禁失败时停止后续阶段，保留当前可运行版本。

### 阶段 0：保护现场与冻结基线

目标：确保任何合并操作都不会覆盖两边现有工作。

执行内容：

1. 在 `GEOWorkFlow` 为 Admin UI V2 预览改动建立独立归档分支和提交。
2. 在 `GEOWorkFlow-UI-V3` 把已提交 UI V3、未提交 AI 工作台、错误弹窗和分发安全改动拆成可追溯提交。
3. 把 UI V3 分支导入 `GEOWorkFlow` 的本地 Git 对象库，保留原始提交哈希和归档引用。
4. 在 `GEOWorkFlow` 创建 `codex/geoflow-ui-v3-unification` 集成分支和独立干净工作树。
5. 将两边状态、提交、未跟踪文件和差异摘要写入迁移清单。
6. 生成旧数据库逻辑备份、文件归档、文件清单和校验值，放入仓库外的 `../GEOWorkFlow-recovery/20260823/`。
7. 从备份恢复一套临时数据库，验证备份可以使用。

阶段门禁：

- 两个原目录无文件丢失。
- 两边 WIP 都有可定位的归档引用。
- 数据库备份可以成功恢复。
- 文件清单包含数量、总字节数和 SHA-256。
- 集成工作树干净，基础测试可以启动。

### 阶段 1：导入 UI V3 公共壳层与全后台页面

目标：在旧数据克隆环境中运行完整 UI V3，不接入 AI 执行。

执行内容：

1. 导入 UI V3 已提交序列和公共组件。
2. 合并 `AdminUiRegistry`、侧栏、顶部栏、最近处理、账户区、页面标题、表格、表单、弹窗和响应式布局。
3. 保留现有 254 条后台路由和原业务控制器。
4. 增加账户中心 3 条路由，并沿用后台鉴权策略。
5. 在旧数据克隆环境验证 97 条原 GET/HEAD 路由和 6 条新增 GET/HEAD 路由，并用页面清单区分可视页面、数据接口、下载和跳转。
6. 验证普通管理员、超级管理员和登录失效三种身份。
7. 将本地 Nginx 网关接入候选环境，检查资源缓存和页面刷新。

阶段门禁：

- 原有后台路由数量和命名保持完整。
- 旧数据克隆中的表格、长文本、分页、空状态和异常状态正常。
- 菜单、最近处理和快捷入口不会展示无权限路由。
- 表单字段、CSRF、验证错误、上传、导出、删除确认和轮询行为保持兼容。
- 主题和前台页面继续使用旧设置。
- 页面刷新无旧样式闪现，浏览器控制台无未处理错误。

### 阶段 2：完成 AI 工作台页面体验

目标：完成用户已经确认的首页、输入、加载、历史和错误体验，运行时继续关闭。

#### 首页布局

- 首页内容轨道固定为 `720px`，输入框、标题区、快捷建议、运行提示、能力说明卡和安全说明使用同一宽度。
- 对话态内容轨道为 `840px`，保证消息阅读和长计划展示空间。
- 页面外层最大宽度为 `1040px`，只用于居中和响应式留白。
- 手机端使用 16px 页面边距，输入区和操作区不产生横向滚动。
- 历史会话只放在左侧“最近处理”，页面内不再出现第二套历史栏。

#### 输入与提交

- 文本框可以输入、粘贴和多行编辑，最大 4000 字。
- 空内容、纯空格和提交中的重复点击不得发送。
- `Enter` 发送，`Shift + Enter` 换行，中文输入法组合状态下不误发送。
- 提交后保留消息内容到本地和会话记录，失败时恢复原输入。
- 新建会话、历史会话切换和页面刷新后状态一致。
- 发送按钮有禁用、可提交、处理中和重试四种状态。

#### Agent 处理中样式

- 发送后 1.5 秒内显示“正在理解任务”。
- 随后按真实状态显示“正在补充信息”“正在生成计划”“等待确认”“正在执行”“正在整理结果”。
- 使用轻量脉冲点、骨架行和步骤状态，不使用模拟百分比。
- 处理超过正常时间时显示解释和取消按钮。
- Reverb 中断时显示“正在同步最新状态”，并自动回退到快照轮询。

#### 居中错误弹窗

错误弹窗固定在页面正中，使用遮罩和单一焦点。页面顶部不再重复显示同一条错误 Toast。

错误类型与按钮：

| 场景 | 标题 | 主按钮 | 次按钮 |
|---|---|---|---|
| 运行时关闭 | 暂时无法发送这条消息 | 有权限时“去配置 AI 模型”，无权限时“我知道了” | “继续编辑” |
| 模型未配置或未通过检测 | AI 模型还未准备好 | “去 AI 配置器” | “保留内容并关闭” |
| 网络或服务暂时不可用 | 连接没有完成 | “重新发送” | “继续编辑” |
| 登录失效 | 登录状态已失效 | “重新登录” | “复制输入内容” |
| 权限不足 | 当前账号无法执行此操作 | “返回 AI 工作台” | “查看可用能力” |
| 结果未知 | 操作结果需要人工确认 | “查看分发记录”或对应业务记录 | “关闭” |

弹窗必须满足以下要求：

- `role="alertdialog"`、标题和描述关联完整。
- 打开后焦点进入弹窗，Tab 焦点锁定，Esc 和关闭按钮行为一致。
- 关闭后焦点回到原触发位置。
- 用户输入不会因为弹窗打开、关闭或跳转而丢失。
- 后端错误只展示经过脱敏的用户文案，日志保留可追踪错误码。

阶段门禁：

- 输入、发送、快捷键、失败恢复和重复提交测试通过。
- 六类错误弹窗的文案、按钮、权限和焦点行为通过。
- 1440、1280、1024、768、390、320 六种宽度通过截图对比。

## 11. 回退方案

### 11.1 UI 回退

观察期内将 `GEOFLOW_ADMIN_UI_V3_ENABLED=false`，刷新配置缓存并重启 App/Web。页面回到旧壳层，数据库和业务数据不变。

### 11.2 AI 回退

将 `GEOFLOW_AI_WORKSPACE_RUNTIME_ENABLED=false`，刷新配置缓存并重启相关 Worker。系统停止接收新消息、审批、计划修改和重试，继续允许查看历史、Run 快照和取消执行中任务。

### 11.3 发布回退

回到上一个已验证镜像或提交，恢复旧 Nginx 路由。保留新增 AI 表和列，不执行默认 `down()`。若数据库迁移本身失败，在维护窗口内使用迁移前逻辑备份恢复，并同步恢复对应文件快照。

### 11.4 外部操作处理

- 已确认成功的外部操作保留记录，不做自动反向操作。
- 已发出且无法确认的操作进入 `outcome_unknown`，人工对账后处理。
- 未发出的步骤安全取消。
- 回退过程禁止对 `outcome_unknown` 自动重试。

## 12. 风险与处理

| 风险 | 触发条件 | 处理 |
|---|---|---|
| 两边 WIP 被覆盖 | 直接复制或切分支 | 阶段 0 先归档提交，使用独立干净工作树 |
| 演示数据覆盖旧数据 | 运行 UI V3 Seeder 或复制 `.env` | 正式禁用演示 Seeder，只用旧 `.env` 合并新键 |
| 加密密钥失效 | `APP_KEY` 改变 | 保留旧值并在克隆库验证模型密钥解密 |
| 大数据页面布局退化 | 只在小演示库验收 | 所有页面必须在旧数据克隆验证 |
| Worker 重复执行 | 超时与 `retry_after` 配置错误 | 保持 900/930/960 秒边界，校验幂等和租约 |
| 外部写结果不确定 | 网络超时发生在远端成功之后 | 写操作账本、稳定幂等键、`outcome_unknown` 和人工对账 |
| 页面刷新闪旧样式 | 动态页或资源缓存错误 | Nginx 分离指纹资源、普通资源和动态 HTML 缓存 |
| 权限入口泄露 | 菜单、最近处理与路由判断不一致 | 共用路由权限注册表，按身份跑全页回归 |
| 回退删除会话数据 | 执行共享会话表 `down()` | 以开关和代码回退为主，保留共享表 |
| 清理误删旧数据 | 容器或目录目标过宽 | 只匹配 `geoflow-ui-v3-*` 和 `GEOWorkFlow-UI-V3`，清理前复核清单 |

最脆弱的假设是 UI V3 在小型演示数据上成立后，也能直接承载旧系统更大的列表、长文本、复杂设置和 154 MB 文件。旧数据克隆验收是正式切换的硬门禁，任何关键页面失败都会暂停切换。
