## 授权与执行链路

### 持续授权

运行创建时保存当前管理员授权版本。解析、审批、计划修改、重试、步骤领取、能力执行、流式批次保存和实时广播都会读取当前管理员状态。下面任一条件发生变化，运行立即停止继续处理：

- 管理员账号停用或删除；
- `admin_auth_version` 为空、为 0 或与当前版本不一致；
- AI 工作台运行时关闭；
- 当前能力权限、版本或可执行状态变化；
- Step 租约或 Resolution 租约被其他 Worker 接管；
- Run 已取消或进入终态。

内部读写能力在同一事务中完成授权复核和结果落库。外部操作继续使用准备记录、幂等键、结果对账和 `outcome_unknown` 保护。

### 终态规则

终态收口遵循固定优先级：

1. 已发出外部请求且结果无法确认时，保留 `outcome_unknown`。
2. 存在已完成 Step 或 Artifact 时，使用 `partially_completed` 并汇总已确认结果。
3. 没有完成结果时，根据触发原因进入 `cancelled` 或 `failed`。
4. 同一 Run 的 AI 回复使用幂等 upsert，重复回调不会新增第二条消息。

## 流式回答与恢复

新增的 Run 字段包括：

- `resolution_source`
- `resolution_started_at`
- `resolution_finished_at`
- `queued_at`
- `first_token_at`
- `answer_chunk_sequence`
- `answer_is_partial`

四个性能时间字段使用微秒精度。AnswerDelta 的 `chunk_sequence` 与数据库中的 `answer_chunk_sequence` 对应。浏览器会拒绝重复批次、旧 Run 批次和终态后的迟到批次；断线恢复时直接采用 Snapshot 中已经持久化的回答与序号。

模型调用设置了总截止时间和单次尝试上限，避免 SDK 多供应商故障转移超过解析 Worker 的 120 秒处理窗口。

## 队列与实时链路

| 工作负载 | 队列 | Worker 超时 | 停止宽限 |
|---|---|---:|---:|
| 问候、规则解析、只读统计、普通回答 | `ai-workspace-interactive` | 150 秒 | 180 秒 |
| 已校验工作流与受控能力执行 | `ai-workspace` | 930 秒 | 960 秒 |

本地、生产和预构建三套 Compose 均完成拆分。通用 Queue 不再消费两条 AI 队列。Horizon 保留两个独立 Supervisor，禁止与 Compose Worker 同时消费相同队列。

队列重试边界：

- Redis、Database、Beanstalkd 的 `retry_after` 不低于 960 秒。
- SQS 需要把真实 Visibility Timeout 配置为大于 930 秒，并通过 `SQS_VISIBILITY_TIMEOUT` 声明相同数值。应用启动时会阻止不安全配置。
- Reverb 客户端连接上限为 500ms，总请求上限为 1 秒。广播熔断后继续持久化，页面自动进入轮询恢复。

- 首屏加载最新 200 条消息。

### 真实状态与错误引导

- 本轮状态只读取终态、最新运行中 TraceEvent、运行中 Step 和 Run 持久状态。
- 页面不会补造模型私有推理，也不会把初始化审计事件当成用户可见步骤。
- 模型未配置、运行时关闭、登录失效和网络异常使用居中弹窗，包含保留草稿说明和明确操作按钮。
