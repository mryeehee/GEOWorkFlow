# 知识库 23：原子事实与知识库检索 AI 质检对照测试报告

- 测试时间：2026-08-30（Asia/Shanghai）
- 知识库：23「GEOFlow 官方分发主题与生态知识（2026-08）」
- 模型：DeepSeek V4 Pro（模型记录 ID 3，`deepseek-v4-pro`）
- 样本：4 篇真实关联文章
- 模型请求：8 次（每篇文章 × 2 种证据方式 × 1 次）
- 评测性质：小样本探索性影子评测

## 一、结论摘要

原子事实证据显著降低了资源消耗：总 Token 从 41,804 降至 24,744，降幅 40.81%；平均单篇耗时从 15.32 秒降至 11.83 秒，降幅 22.77%，约为 1.29 倍速度。

当前质量裁决仍未达到上线要求。两种方式的最终 decision 准确率均为 25%。原子方式识别出唯一的明确版本冲突，知识库检索方式漏掉该冲突；两种方式均对 3 篇安全文章中的 2 篇产生误报。原子方式的问题集合精确一致率为 50%，知识库方式为 25%。

本轮调用现有通用 AI 质检提示词和确定性评分器，只替换证据载荷。专用的“原子指标匹配 → 标准值比较 → 硬性裁决”链路尚未接入文章质检。因此，本轮结果证明了原子证据的成本优势，也暴露了评分规则、适用性判断和专用比较器的集成缺口。

## 三、评测设计

### 3.1 控制变量

两组使用相同的模型、完整文章、事实候选、质检日期、通用质检提示词、结构化输出校验器和后端评分器。唯一变量为证据载荷：

- 原子方式：每篇注入 1 至 3 条相关原子事实标准答案，证据正文 21 至 327 字符。
- 知识库方式：调用现有知识检索服务，每篇注入 7 个切片，证据正文约 6,000 字符。

模型返回的提供商 usage 用于 Token 统计；`hrtime` 墙钟时间用于延迟统计。准确性依据人工对照知识库 23 工作版本 v3 得到的黄金裁决。

## 五、发现的问题

1. **事实库尚未发布。** 服务状态为 `unavailable`，当前文章质检不会把该事实库作为生产依据。
2. **原子事实尚未接入文章质检主链路。** 当前生产质检仍走事实候选提取、知识切片检索和通用大模型审核。
3. **通用评分器没有原子级强制规则。** 明确版本冲突被识别后仍得到 90 分和 `needs_review`。
4. **适用性判断容易误报。** 原子事实包含完整能力列表时，模型可能把文章未覆盖全部字段理解为矛盾或缺失。
5. **版本号比较能力不足。** 现有确定性 `AtomicFactComparator` 擅长普通数值和严格文本包含；`v2.1.1` 与 `v2.1.0` 这类语义化版本需要专门规范化与不等判断。
6. **固定提示词成本较高。** 原子方式已经压缩证据，完整广告合规提示词和通用输出 Schema 仍占主要输入成本。
7. **decision 与 issues 存在不一致。** 样本 473 的知识库结果为 `passed`，同时输出 `knowledge_contradiction`；样本 467 为 100 分、无问题，却进入 `needs_review`。评分、覆盖门禁和问题严重度需要统一解释。

## 六、建议升级顺序

### P0：闭合可用链路

1. 完成 20 条事实和标准值的人工审核，发布 active revision；只有 `serving_status=available` 的修订参与自动质检。
2. 在文章质检入口增加事实库路由：优先读取已发布原子事实；没有可用事实库时回退知识库切片检索。
3. 增加原子适用性阶段，输出 `matched / not_mentioned / ambiguous`。`not_mentioned` 不扣分；文章明确声称“完整配置”“全部能力”时才检查完整集合。
4. 把原子比较结果接入确定性评分：高重要度 `mismatch` 直接阻断，并设置分数上限；`unknown` 进入人工复核；`match` 通过。
5. 将事实修订 ID、命中事实 key、比较结果、标准值哈希和回退原因写入质检快照，保证可追溯。

### P1：增强比较器

1. 增加语义化版本、日期、枚举、布尔、集合和路径类型的规范化比较。
2. 数字比较固定执行主体、数值、单位、时间和范围五元组校验；标准值允许显式容差时才启用容差。
3. 文本类先做别名和同义表达归一化，再进行轻量语义相似度判断；出现数字或版本时由确定性比较覆盖语义结果。
4. 集合类支持 `exact / contains / subset` 三种策略，避免把摘要文章误判为能力缺失。
5. 为每种比较策略建立契约测试，并覆盖中文数字、百分比、单位换算、版本号和路径占位符。

### P2：成本与评测治理

1. 为原子模式设计轻量提示词，只保留主张定位、适用性、语义等价和结构化输出；广告合规与全文完整性可在独立检查器中按需运行。
2. 遥测增加 `inspection_mode`、`fact_revision_id`、`matched_fact_count`、`fallback_reason`、比较器耗时和分阶段 Token。
3. 建立至少 30 至 50 篇人工标注集，包含正确改写、数字错误、版本错误、单位换算、未提及事实和范围扩大。
4. 每个样本执行 3 至 5 次交替顺序测试，报告准确率、冲突召回率、误复核率、P50/P95 Token、P50/P95 延迟和决策稳定率。
5. 上线门禁建议：重大事实冲突召回率 ≥97%，安全样本误拦截率 ≤3%，decision 一致率 ≥95%，输入 Token 相比知识库模式下降 ≥35%。

## 七、最终判断

原子事实方案具备明确的工程价值。本轮在真实文章和真实模型上实现了 40.81% 总 Token 降幅、22.77% 时间降幅，并提高了明确版本冲突的发现能力。

当前版本适合继续以 shadow 模式运行。生产切换条件包括事实库正式发布、专用适用性判断、类型化比较器、硬性评分规则和足够规模的人工黄金集。完成 P0 后建议立即复测同一批文章，再扩展至 30 至 50 篇回归集。
